<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend → PVE API (self-signed TLS) | The PVE certificate is untrusted CA-wise; the connection must be validated against a pinned fingerprint |
| external client → /auth/login | Brute-force surface; rate limiting and constant-time responses must hold across workers |
| browser → SvelteKit-served SPA | The SPA must run under a CSP that blocks injected scripts |
| PAT bearer → API | A PAT for a disabled user must be rejected and the rejection observable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Tampering / Info Disclosure | PVE API connection (MITM on self-signed TLS) | mitigate | TOFU fingerprint pinning (D-20) — `urllib3 assert_fingerprint` via `FingerprintPinningAdapter`. The admin confirms the SHA-256 once at register-time; every subsequent connection is validated against it. Replaces `verify_ssl=False`. |
| T-05-02-02 | Tampering | TLS pin that silently cannot fail | mitigate | A negative test (wrong-cert host MUST be refused) is written FIRST (Pitfall 4). If the proxmoxer mount seam is unreliable, a stdlib `ssl` pre-flight fallback is used — pinning that cannot fail is not shipped. |
| T-05-02-03 | Spoofing (brute-force) | login rate limiter | mitigate | The token bucket moves to Redis (ME-02) — shared state regardless of uvicorn worker count, closing the per-worker N×10 bypass. |
| T-05-02-04 | Information Disclosure | disabled-user login timing leak | mitigate | LO-01 — the `is_active` check moves before `verify_password`, and a dummy Argon2id verify runs on the disabled path so response timing does not leak account-disabled state. |
| T-05-02-05 | Repudiation | PAT used after the owning user is disabled | mitigate | IN-01 — `resolve_pat` writes an `audit_log` entry on first rejection of a disabled-user PAT, making the event observable. |
| T-05-02-06 | Cross-Site Scripting | the SPA without a CSP | mitigate | A `Content-Security-Policy` header is added to Caddy with `default-src 'self'`, `frame-ancestors 'self'`, and `connect-src 'self'` — injected/cross-origin scripts are blocked while SvelteKit hydration still works (`'unsafe-inline'` scoped to script/style only). |
| T-05-02-07 | Tampering / Elevation | cluster PATCH desync (token_user without secret) | mitigate | IN-03 — a `@model_validator` rejects a PATCH that changes `token_user` without `api_token_secret` (or vice-versa), preventing a silently-broken or mismatched connector credential. |
| T-05-02-08 | Spoofing | COOKIE_SECURE=false in production | mitigate | The config validator emits a startup `UserWarning` when `cookie_secure` is False off-localhost, and `deploy/README.md` documents it dev-only — an operator cannot silently ship insecure cookies. |
| T-05-02-09 | Tampering | ssh-rsa key wrongly rejected | accept | The fix restores intended `ssh-rsa` acceptance (a correctness regression, not a new attack surface); `cryptography`'s `load_ssh_public_key` remains the validator — no hand-rolled parsing introduced. |
</threat_model>
