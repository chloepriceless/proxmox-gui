<objective>
Make the product mobile-usable and run an accessibility pass (UI-03). The
inventory list, VM detail, and console reflow on small viewports; the wizards
are gracefully gated (UI-03 exempts them). The accessibility pass is an
automated axe-core audit plus a manual audit checkpoint covering keyboard
navigation, ARIA on the hand-rolled components, contrast, and a screen-reader
smoke test (D-17).

Purpose: UI-03 — list/detail/console reflow on mobile and pass an accessibility
check against shadcn-svelte defaults.

Output: a hamburger drawer (D-13), the inventory card-stack reflow (D-14), the
console scale-to-fit (D-15), the wizard small-screen gate (D-16), an automated
axe-core test (D-17), and a human accessibility-verification checkpoint.

NOTE — frontend build discipline (project constraint): this plan touches
`frontend/`. The acceptance criteria include `pnpm run build` AND the
`git checkout -- frontend/build/node_modules` + `git add -fA frontend/build`
restore dance — a prod build that wipes the git-tracked
`frontend/build/node_modules` must be repaired before staging.
</objective>
