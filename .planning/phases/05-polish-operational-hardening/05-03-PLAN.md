<objective>
Build the audit-log retention/rotation policy (AUDIT-06) and replace the
placeholder cron bodies registered in 05-01. A nightly arq cron rolls
`audit_log` rows past the configured retention window (D-06, default 1 year)
into compressed `CSV.gz` archives, then deletes the rolled rows (D-07). The
archives are listable + downloadable from the admin Audit page (D-08). This
plan also delivers the carryover scheduled cluster health probe — an arq cron
that probes each cluster and persists its status.

Purpose: AUDIT-06 — bounded audit-table growth with no manual intervention,
archived history kept as a downloadable product artifact. Plus the Phase-1
carryover health-probe item (CLUST-06 was wired but never scheduled).

Output: `roll_audit_log` + `probe_clusters` cron bodies; the CSV.gz archive
writer; `GET /api/v1/audit/archives` + `GET /api/v1/audit/archives/{name}`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/audit/archives/{name} | An untrusted path component is used to build a filesystem path |
| worker → PVE API | The health probe reaches out to each cluster on a schedule |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Information Disclosure | audit-archive download endpoint | mitigate | `resolve_archive_path` rejects any `{name}` containing `/`, `\`, or `..`, resolves the path, and asserts `is_relative_to(ARCHIVE_DIR)` (Pitfall 5). Without this, `name=../../etc/proxmox-gui/master.key` would leak the master key. Route is `require_admin`. |
| T-05-03-02 | Information Disclosure | audit-archive listing/download | mitigate | Both archive routes are `require_admin` — archives are the unscoped compliance dump (not RBAC-filtered), so they must never be reachable by a regular user. |
| T-05-03-03 | Repudiation / Data loss | audit row deletion before archive is durable | mitigate | Write-then-delete ordering — `roll_audit_log` writes and closes the `.csv.gz` BEFORE issuing the `DELETE`. A crash between the two leaves rows un-archived but never silently lost. |
| T-05-03-04 | Denial of Service | one unreachable cluster aborting the probe sweep | mitigate | `probe_clusters` wraps each cluster in its own try/except — a `PVEUnreachable` on one cluster is recorded and the sweep continues. |
| T-05-03-05 | Denial of Service | unbounded archive directory growth | accept | Archives are intentionally not auto-pruned in v1 (RESEARCH Open Question 3 — they are the compliance artifact). The admin Audit page surfaces total archive size so an operator can clear manually; auto-prune is a noted v2 enhancement. |
| T-05-03-06 | Tampering | retention window set to an extreme value | accept | `audit_retention_days` is bounded by the `Field(ge=1, le=3650)` validation in plan 05-01's settings schema — it cannot be set to 0 (delete-everything) or absurdly high. |
</threat_model>
