<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/admin/settings, /api/v1/admin/self-update | Admin-only mutation surfaces driven from the SPA |
| browser → /clusters/{id}/verify-ssh | An admin-triggered probe of a cluster's SSH reachability |
| GUI → PVE node (pct exec preflight) | The preflight reaches a node over SSH |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06-01 | Spoofing | client idle timer | mitigate | The client idle timer is UX-only — it drives the warning toast and the proactive keepalive. The authoritative gate is the server-side refresh refusal from plan 05-01; a tampered client clock cannot extend a session past the server's idle window. |
| T-05-06-02 | Elevation of Privilege | admin Settings + self-update pages | mitigate | The Settings page has a `+page.server.ts` admin auth gate (defence-in-depth re-check beyond the layout gate); the underlying APIs are `require_admin`-gated server-side. |
| T-05-06-03 | Information Disclosure | session-expired modal preserving page state | accept | The modal overlays the current route without navigating; the underlying page's already-rendered (already-authorised) data stays visible behind the modal. This is the intended D-03 UX — no new data is fetched while expired, and the re-auth restores a valid session before any further API call. |
| T-05-06-04 | Tampering | GUI public key displayed in the registration UI | accept | The displayed value is a PUBLIC key — exposing it is its purpose (the admin pastes it into each node's `authorized_keys`). The private key never leaves `/etc/proxmox-gui/`. |
| T-05-06-05 | Elevation of Privilege | community-script deploy without SSH trust | mitigate | The D-23 preflight gate blocks the community-script wizard path when `pct exec` is unreachable, with a guided fix — preventing a half-trusted deploy. Plain-LXC/VM paths (which need no SSH) stay available, so the gate is scoped, not a blanket block. |
| T-05-06-06 | Spoofing | /clusters/{id}/verify-ssh trigger | mitigate | The verify-ssh route is admin-gated; it only probes reachability of an already-registered cluster and returns a boolean — it accepts no credentials and performs no mutation. |
</threat_model>
