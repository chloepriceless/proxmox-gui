# Phase 3 — UI Design Contract

> Visual and interaction contract for Job Queue & Lifecycle. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance rule:** This contract **extends** the Phase 1 (`01-UI-SPEC.md`) and Phase 2 (`02-UI-SPEC.md`) contracts. The Design System, Spacing Scale, Typography, Color tokens, Form Patterns, Theme Toggle, and Accessibility Floor sections of the prior specs are the source of truth and **carry forward unchanged**. This document adds only the Phase 3 surfaces, new component contracts, and the icon allow-list deltas. Where Phase 3 needs a new state or pattern that the prior phases did not cover, it is declared here explicitly.
>
> **Stack note (unchanged):** SvelteKit 2 + Svelte 5 + Tailwind v4 + shadcn-svelte. `bits-ui` 2.18.x primitives, `@lucide/svelte` icons, Inter Variable self-hosted, `sonner` Toaster already mounted in `AppShell.svelte` (bottom-right, richColors, closeButton). No design tokens are re-derived — the slate preset, the 4-size/2-weight type ramp, the 8-point spacing scale, and the `--success`/`--warning`/`--destructive` semantic extensions are all locked.

## Design System (inherited)

Inherited verbatim from Phase 1 UI-SPEC §Design System. No changes. Pinned values this phase depends on:

| Property | Value |

| Icon library | `@lucide/svelte` (scoped name) |
| Font | Inter Variable (self-hosted, weights 400 + 500 + 600) |
| Theme strategy | Tailwind v4 `class` strategy on `<html>` |
| Toast | `sonner` (already mounted in AppShell — bottom-right, richColors, closeButton) |
| Forms | shadcn-svelte `form` block (Formsnap + zod 4) |
| Server state | `@tanstack/svelte-query` 6.x |
| Validation | `zod` 4.x |

**shadcn-svelte blocks/components already present** (Phase 1 + 2 — reused, not re-added): button, input, label, textarea, checkbox, switch, select, card, separator, badge, alert, dialog, alert-dialog, dropdown-menu, sheet, form, sonner, table, tabs, tooltip, scroll-area, progress, popover, command, accordion, collapsible, input-group.

**No new shadcn-svelte blocks required for Phase 3.** Every Phase 3 surface composes from the existing primitive set:
- Tasks drawer → `sheet` + `scroll-area` + `collapsible` (batch grouping) + `badge` + `button`
- Snapshot tree → hand-rolled recursive Svelte component using `button` + `badge` (rationale below)
- Backups tab + `/backups` → `table` + `card` + `badge`
- All dialogs → `dialog` (forms) / `alert-dialog` (OK/Cancel confirms) + reuse `ConfirmByNameDialog.svelte`
- Resize / Migrate Advanced disclosure → `collapsible`
- Error detail → `collapsible` inside the Tasks drawer row and the error toast

**Snapshot tree renderer (D-05): hand-rolled recursive component.** No tree-view library is imported. Rationale: snapshot hierarchies in a home-lab are shallow (typically ≤10 nodes, ≤3 branch depth); a recursive Svelte component drawing indent guides with CSS borders is ~80 lines and adds zero bundle weight. This mirrors the Phase 2 decision to hand-roll `Sparkline.svelte` rather than import a chart library. The checker validates the absence of any tree-view npm dependency (`react-arborist`, `svelte-tree`, etc.).

**Elapsed-timer formatting:** elapsed time is computed client-side from the job's `created_at` against a 1s `setInterval` tick. Format: `<60s → "12s"`, `<60m → "4m 12s"`, `≥60m → "1h 04m"`. No date library — a ~12-line formatter. Checker validates no `dayjs`/`luxon`/`date-fns` import for this.

**Icon allow-list — Phase 3 additions** (executor uses ONLY these new icons beyond the Phase 1 + 2 allow-list):

```

Camera, GitBranch, Database, HardDrive, Cpu, MemoryStick,
Copy, FileStack, ArrowRightLeft, BadgePlus,
ListChecks, ChevronsRight,
```

## Color (inherited)

Inherited verbatim from Phase 1 + 2 UI-SPEC §Color. Tokens already declared in `src/app.css` (light + dark slate preset with custom `--success` and `--warning`). **No new tokens introduced.**

### Job state → color mapping

The job state machine (`pending → claimed → running → succeeded/failed/orphaned/needs_review`) maps to the existing semantic palette. This is the contract for the Tasks drawer row, the count badge, and the completion toast:

| Job state | Background | Border | Foreground | Icon | Spinner? |
|-----------|------------|--------|------------|------|----------|
| pending / claimed | `bg-muted` | `border-border` | `text-muted-foreground` | `Clock` | no |
| running | `bg-muted` | `border-border` | `text-foreground` | `Loader2` (animate-spin) | yes |
| succeeded | `bg-success/10` | `border-success/30` | `text-success` | `CircleCheck` | no |
| failed | `bg-destructive/10` | `border-destructive/30` | `text-destructive` | `CircleAlert` | no |
| orphaned | `bg-warning/10` | `border-warning/30` | `text-warning` | `TriangleAlert` | no |
| needs_review | `bg-warning/10` | `border-warning/30` | `text-warning` | `CircleSlash` | no |

The job-row background tint is the **row left-edge bar only** (3px `border-l-2`) plus a tinted status icon — the row body stays `bg-background` so the drawer reads as a clean feed, not a stack of colored cards. This matches the Phase 1 "no information by color alone" floor: every job row carries an icon **and** a state word.

### Tasks count badge color

| Condition | Badge |
|-----------|-------|
| Any job running, none failed | `bg-primary text-primary-foreground` |
| Any job failed (unacknowledged) | `bg-destructive text-destructive-foreground` |
| Only succeeded/idle (count 0) | badge hidden |

A failed job dominates the badge color — the failure signal must not be hidden behind a "3 running" count.

## Layout Contracts

### Tasks drawer (global chrome)

A persistent slide-out activity feed. `Sheet` from shadcn-svelte, side=`right`, 420px wide. Mounted in `AppShell.svelte` alongside the QuotaIndicator drawer.

```
┌─────────────────────────────────────────────┐
│  Tasks                                  [✕]  │  ← Sheet header, Heading 18/600
│  3 running · 1 failed                         │  ← summary line, Body 14/400 muted
├─────────────────────────────────────────────┤
│ ┌─ batch ──────────────────────────────────┐ │
│ │ ▾  Bulk reboot ×5   2 done · 3 running    │ │  ← batch header, h-10, bg-muted/40
│ ├──────────────────────────────────────────┤ │
│ │ ⟳  Reboot vm-101         running   0m 12s │ │  ← job row, left-edge tint bar
│ │    UPID:UPID:node-01:000A...               │ │
│ │ ✓  Reboot vm-102         done      0m 08s │ │
│ └──────────────────────────────────────────┘ │
│                                                │
│ ⟳  Backup vm-200          running   2m 41s    │  ← standalone long job
│    INFO: creating vzdump archive               │  ← backup INFO: lines (D-04)
│    INFO: 34% (1.2 GiB of 3.5 GiB)              │
│                                                │
│ ✕  Migrate vm-150         failed    1m 03s    │
│    VM is locked — unlock it from the detail   │  ← friendly error (D-13)
│    page, then retry.                           │
│    ▸ Show technical details                    │  ← collapsible (D-14)
│    [ ↻ Retry ]   (idempotent ops only — D-16) │
└─────────────────────────────────────────────┘
```

**Drawer header contract:**
- Title "Tasks" (Heading 18/600)
- Summary line below (Body 14/400 muted): live counts — `"{N} running · {N} failed"`; when all idle: `"No active tasks"`
- Standard `Sheet` close `X` top-right

**Open / auto-open behavior (D-02):**
- The drawer **auto-opens** when a long job is enqueued: `clone`, `migrate`, `backup`, `restore`
- Fast power actions (`start`, `stop`, `reboot`, `shutdown`) do **not** auto-open the drawer — they leave it collapsed and bump the Topbar count badge; the enqueue toast confirms them
- The user can always open the drawer manually via the Topbar Tasks icon
- Once open, the drawer stays open until the user closes it (no auto-close on job completion)

**Scope (D-01):** team-wide. The drawer shows every job across every team the user belongs to. No per-user filter toggle. Job rows do not show an actor name in v1 (team-shared resources; actor is in the audit log) — but the WebSocket payload carries it for a future enhancement.

**Job row contract:**
- min 56px tall, grows when error-detail or `INFO:` lines expand
- 3px left-edge tint bar per job state (see Color §Job state mapping)
- Line 1: state icon (16px) + task-type label (Body 14/400, e.g. "Reboot vm-101") + elapsed timer (Mono 13/400 tabular-nums, right-aligned)
- Line 2: UPID (Mono 13/400 muted, truncate with full value in `title`)
- Running jobs show `Loader2` spinning; the elapsed timer ticks every 1s
- Backup jobs additionally render structured `INFO:` lines in a `--muted` mono block below line 2 (D-04) — last 5 lines, `whitespace-pre-wrap`
- Failed jobs render the friendly error message (Body 14/400) + a "Show technical details" collapsible + the Retry button when idempotent

**Batch grouping (D-11):**
- Bulk jobs are grouped under a `collapsible` batch header (40px, `bg-muted/40`)
- Header shows: chevron, batch label ("Bulk reboot ×5"), and a running tally ("2 done · 3 running"; "5 done" when complete; "3 done · 2 failed" on partial failure)
- Batch is **expanded by default** while any child is running; collapses to a one-line summary once all children finish
- Each child is a normal job row, indented 16px under the header

**Ordering:** newest-first; running jobs float above completed jobs within their batch / the flat list. A completed job stays in the drawer for the session (the WebSocket backfills the recent window on reconnect — see WebSocket contract); there is no "Clear" button in v1 (Claude's-discretion item — drawer auto-trims to the most recent 50 jobs client-side).

**Empty state:** centered, `2xl` vertical padding — `Activity` icon (24px muted), heading "No tasks yet" (Heading 18/600), body "Lifecycle actions you run will show their progress here." (Body 14/400 muted).

**WebSocket / reconnection contract (Claude's discretion — pinned here):**
- The drawer subscribes to `wss://…/api/v1/ws/jobs` on mount
- On a dropped connection: show an inline `Alert variant="warning"` strip at the top of the drawer body — "Reconnecting to live updates…" with a small `Loader2`
- On reconnect: the server replays the recent job window (last 50 / last 1h); the drawer reconciles by `job.id` (no duplicate rows)
- While disconnected, elapsed timers keep ticking client-side from `created_at` so the UI never freezes

### Topbar — Tasks icon (modification)

- A new icon button mounts in the Topbar **right cluster**, positioned **left of the QuotaIndicator block** (order left→right: `[Tasks] [Quota] [ThemeToggle] [UserMenu]`)
- Icon: `ListChecks` (16px), button `h-9 w-9`, `variant="ghost"`
- Live count badge overlapping top-right: 18px circle, shows the in-flight (running + pending) job count; hidden at 0; `9+` above 9
- Badge color per Color §Tasks count badge (primary when running, destructive when any unacknowledged failure)
- `aria-label="Tasks: {N} running, {N} failed. Open task drawer."`
- Click toggles the Tasks drawer
- A failed-job badge stays red until the user opens the drawer (opening the drawer acknowledges failures)

### Lifecycle action toolbar (`/inventory/{cluster}/{vmid}` — modification)

A 44px-tall toolbar between the detail page header block and the tab strip.

```
┌──────────────────────────────────────────────────────────────────────┐
│  ● running   vm-name                            Display 28/600        │
│  Mono: 100 · Cluster-A · node-01                 Body 14/400 muted     │
├──────────────────────────────────────────────────────────────────────┤
│  ACTION TOOLBAR  h-11                                                  │
│  [▶ Start] [⏹ Stop] [↻ Reboot] [⏻ Shutdown]   [⋯ More ▾]   [🗑 Delete]│
├──────────────────────────────────────────────────────────────────────┤
│  TAB STRIP  [Overview][Activity][Snapshots][Backups][Console ✱]       │
└──────────────────────────────────────────────────────────────────────┘
```

**Toolbar contract:**
- Primary power cluster (left): Start, Stop, Reboot, Shutdown — all `Button variant="outline" size="sm"` (`h-9`), icon + label, `sm` gap between them
- Buttons are **context-aware**: when the VM is running, Start is disabled; when stopped, Stop/Reboot/Shutdown are disabled. Disabled buttons keep their place (no layout shift) at `opacity-50`.
- "More" `DropdownMenu` (`variant="outline" size="sm"`): groups the lower-frequency lifecycle ops — Snapshot, Back up now, Resize, Clone, Migrate, Convert to template. Each item has its Phase-3 icon + label.
- Delete sits **far right**, visually separated by `flex` spacer + a 1px `--border` divider, `Button variant="destructive" size="sm"` with `Trash2` icon. Physical separation from the power cluster reduces misclick risk.
- Each toolbar action opens its dialog (see Dialog Contracts) — no toolbar action mutates directly.
- While a job is in flight for this VM, all toolbar buttons are disabled with a tooltip "An action is already running for this resource."

### Inventory list — per-row menu + bulk select (modification)

**Per-row "⋯" power menu (D-09):**
- Each `/inventory` row gains a `MoreHorizontal` `variant="ghost"` `h-9 w-9` button in the rightmost area, **left of** the existing `ChevronRight` affordance
- Clicking it opens a `DropdownMenu` scoped to quick power actions only: Start, Stop, Reboot, Shutdown — context-aware (disabled per current status) — plus a separator and "Open detail →"
- Delete is **not** in the row menu — Delete requires the detail page (forces the user to the fuller context before a destructive op)

**Bulk-select mode (D-11, LIFE-03):**
- The filter row gains a "Select" toggle button (`variant="outline" size="sm"`, `ListChecks` icon). Activating it reveals a 40px checkbox column at the left of every row and a header "select all (filtered)" checkbox.
- When ≥1 row is checked, the **bulk-action bar** slides in: 56px tall, `bg-muted`, sticky directly under the filter row.
- Bulk-action bar contents — left: "{N} selected" (Body 14/400) + "Clear selection" link; right: `[▶ Start] [⏹ Stop] [↻ Reboot]` buttons (`variant="outline" size="sm"`). **No bulk Delete** (ROADMAP-locked, deliberately absent).
- A bulk action opens a **single** confirm dialog covering the whole batch (see Dialog Contracts §Bulk confirm), then fans out one job per VM; the Tasks drawer groups them under a batch header (D-11).
- Bulk actions cross clusters: if the selection spans two clusters, the jobs fan out per-cluster but still group under one batch header.
- Exiting bulk-select mode (toggling "Select" off, or "Clear selection") removes the checkbox column and hides the bar.

**Snapshot tab contract:**

## Error Presentation Contract (D-13, D-14, D-15, UI-06)

The single most important Phase 3 UX surface. Errors are **never swallowed** (Pitfall 24).

**Layered presentation:**
1. **Friendly message first.** A curated map of common PVE error patterns → human text + suggested fix. Canonical example: a locked VM → "VM is locked — unlock it from the detail page, then retry." The friendly message is Body 14/400 `text-foreground`.
2. **Raw fallback.** When an error does not match the curated map, the raw PVE message is shown directly as the friendly line — never replaced with a generic "operation failed".
3. **Expandable technical detail (D-14).** A `collapsible` labelled "Show technical details" (chevron + Label 13/500). Expanded, it reveals: raw stderr, the UPID, and the task-log tail — all Mono 13/400 inside a `--muted` block, `whitespace-pre-wrap`, `max-h-64` scroll.
4. **No redaction (D-15).** All users see the full technical detail. No admin/non-admin gating. (Conscious deviation from Pitfall 24's redaction advice, accepted for the small-team home-lab audience.)

**Where errors appear:**
- **Failed-job toast (D-03):** sonner error variant, sticky (does not auto-dismiss — matches the Phase 1 toast rule for errors). Shows the friendly message + an "Open in Tasks" action linking to the drawer.
- **Failed-job row in the Tasks drawer:** friendly message inline + the "Show technical details" collapsible + the Retry button (when idempotent).

**Curated error map — the contract for the most common entries** (the planner/executor maintain the full table; these are locked):

| PVE error pattern | Friendly message |
|-------------------|------------------|
| VM/CT is locked (`can't lock file` / `VM is locked`) | "VM is locked — unlock it from the detail page, then retry." |
| Insufficient resources on target node | "The target node doesn't have enough free CPU or memory. Pick another node." |
| Storage not available / not active | "The storage for this operation isn't available right now. Check the cluster, then retry." |
| Migration: node-local resource (Pitfall 20) | "This VM references a file that only exists on its current node. It can't be migrated until that's resolved." |
| Cluster not quorate (Pitfall 18) | "The Proxmox cluster has lost quorum — writes are paused until it recovers." |
| Backup target full / no space | "The backup storage is out of space. Free up space or reduce retention." |
| Disk shrink attempted | "Disks can only grow. Shrinking is not supported by Proxmox." |
| Timeout reaching the node | "Couldn't reach the Proxmox node in time. It may be busy — try again shortly." |
| Permission denied (privsep token) | "Your team's token can't perform this action on this resource. Contact an administrator." |
| Unrecognized | (raw PVE message verbatim — never "operation failed") |

## Retry Affordance Contract (D-16, LIFE-13)

- A one-click "Retry" button appears on a **failed** job row in the Tasks drawer **only** for idempotent ops: `start`, `stop`, `reboot`, `shutdown`, `snapshot-delete`, `resize`, `backup`. Keyed off `jobs.idempotency_key`.
- Non-idempotent ops (`clone`, `migrate`, `delete`, `restore`) show **no** Retry button — the user re-issues from the originating form/dialog.
- Retry button: `Button variant="outline" size="sm"`, `RotateCw` icon, label "Retry". It is **not** accent-colored (retry is a recovery action, not the page's primary CTA).
- On click: re-enqueues the same operation; the failed row updates in place to `pending → running` (it does not spawn a second visible row — the job re-uses its identity).
- While retrying, the button shows `Loader2` + "Retrying…" and is disabled.

## Accessibility Floor (Phase 3)

Inherits the Phase 1 + 2 accessibility floor. Phase 3-specific minimums:

- The Tasks drawer is a `Sheet` — `bits-ui` provides `role="dialog"` + focus trap + ESC-close. The Tasks Topbar button has `aria-label` with the live count (see Topbar contract).
- Job rows announce state changes: each row's state word (`running` / `failed` / etc.) is real text, and the state region has `aria-live="polite"` so a job finishing is announced once.
- Status is **never color-only**: every job row, snapshot node, and backup status carries an icon **and** a text label (carries forward the Phase 1 rule).
- The elapsed timer is decorative for screen-reader purposes (`aria-hidden` on the ticking value) — the state word carries the meaning; a constantly-updating timer would spam the live region.
- All toolbar and row-menu actions are keyboard reachable; disabled buttons keep `aria-disabled` + a tooltip explaining why.
- Typed-name confirm fields (via `ConfirmByNameDialog`) keep the Phase 1 a11y contract (label, inline hint, no ENTER-submit).
- The snapshot tree is a `role="tree"` with `role="treeitem"` nodes and `aria-expanded` on branch nodes; arrow-key navigation is the bits-ui-free hand-rolled component's responsibility — the executor implements roving tabindex.
- Contrast: all Phase 3 surfaces reuse Phase 1 tokens already validated AA in both modes — no new colors, so no new contrast risk.

## Implementation Notes for Executor

1. **Power actions are built first.** They exercise the full enqueue → worker → UPID-poll → WebSocket → drawer → toast pipeline end-to-end before clone/migrate/backup are layered on (research SUMMARY.md). Build the Tasks drawer + WebSocket client + the Start/Stop/Reboot/Shutdown toolbar as one vertical slice.
2. **Every mutating endpoint returns `202 Accepted` + job id** — no UI surface ever blocks on a UPID poll. The toolbar buttons show a brief loading state only for the enqueue round-trip, then hand off to the drawer.
3. **The Tasks drawer mounts in `AppShell.svelte`** alongside the existing QuotaIndicator drawer — both are `Sheet` side=`right`. They are mutually exclusive (opening one closes the other).
4. **The Snapshots tab `Lock` marker is removed** from the tab trigger in `inventory/[cluster]/[vmid]/+page.svelte`; the Console trigger keeps its `Lock` + "Console ships in Phase 4" tooltip. A new Backups trigger is added between Snapshots and Console.
5. **The snapshot tree is a hand-rolled recursive Svelte component** — no tree-view npm dependency. Indent guides are CSS borders. Mirrors the Phase 2 hand-rolled `Sparkline.svelte` decision.
6. **`ConfirmByNameDialog.svelte` is reused verbatim** for Delete, restore-snapshot, in-place restore-from-backup, delete-snapshot, delete-backup-file. Do not author a new typed-name dialog.
7. **bwlimit must remain visible** in the Migrate dialog — it lives inside the Advanced `collapsible`, never removed (D-12, success-criterion). The Advanced section is collapsed by default but always present.
8. **No `skiplock` field anywhere** in the UI (Pitfall 17, ROADMAP-locked).
9. **No bulk Delete** — the bulk-action bar has Start/Stop/Reboot only (ROADMAP-locked exclusion).
10. **Errors are never swallowed** — unrecognized PVE errors show their raw message verbatim as the friendly line; the curated map only improves recognized patterns. No "operation failed" string may appear in implemented UI.
11. **All copy in this contract is the user-facing copy** — executor uses it verbatim. Changes require updating this spec, not silently in code.
12. **No new design tokens, sizes, weights, or icons beyond the cumulative allow-list.** Phase 3 composes entirely from the established slate design system.
