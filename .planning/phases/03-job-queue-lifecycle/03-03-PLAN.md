<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → snapshot/resize routes | Untrusted requests; CSRF + RBAC gate every mutation |
| worker → Proxmox | Snapshot/config calls as the per-team privsep token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Elevation of Privilege | Snapshot/resize on another tenant's VM | mitigate | Every route depends on `require_resource_access` — 403 on cross-tenant before any enqueue; the worker executes as the team privsep token. |
| T-03-03-02 | Spoofing / CSRF | Snapshot/resize mutations | mitigate | Every mutating route carries `Depends(csrf_protect)`. |
| T-03-03-03 | Tampering | Disk shrink to corrupt a filesystem | mitigate | `validate_resize` rejects any `new_size_gb <= current` with 422 server-side — the UI `min` is a UX affordance only; the API is the enforcement point (LIFE-09). |
| T-03-03-04 | Elevation of Privilege | `skiplock` via resize body | mitigate | `ResizeRequest` uses `extra="forbid"`; `skiplock` is not a field. Acceptance criterion greps 0 occurrences. |
| T-03-03-05 | Input Validation | Malformed disk identifier reaching proxmoxer | mitigate | `DiskGrow.disk` is validated as a string; the service only resizes disks already present in the parsed VM config — an unknown disk id has no current size and is rejected. |
| T-03-03-06 | Repudiation | Snapshot/resize with no audit trail | mitigate | Enqueue writes an audit row; the worker writes the outcome audit row on success and failure (Phase 2 D-20). |
</threat_model>
