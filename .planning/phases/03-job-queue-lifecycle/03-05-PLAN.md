Backend routes (Plan 02):
- POST /api/v1/clusters/{id}/vms/{vmid}/power  body {action:"start"|"stop"|"reboot"|"shutdown"} → 202 {job_id, state, kind}
- DELETE /api/v1/clusters/{id}/vms/{vmid} → 202
- POST /api/v1/clusters/{id}/vms/bulk-power body {action, targets:[{cluster_id,vmid}]} → 202 {batch_id, job_ids}
- GET /api/v1/jobs?state=&limit= → {jobs:[JobResponse], running, failed}
- GET /api/v1/jobs/{id} → JobResponse
- POST /api/v1/jobs/{id}/retry → 202
- WebSocket /api/v1/ws/jobs → on connect: {type:"backfill", jobs:[...]}; then {type:"job.running"|"job.progress"|"job.completed", job:{...}}; {type:"reaper.reattached", job_ids:[...]}
JobResponse fields: id, kind, state, cluster_id, team_id, upid, upid_node, error, friendly_error, batch_id, created_at, started_at, finished_at.

Frontend conventions (REUSE — do not re-invent):

- frontend/src/lib/api/client.ts — has an EXTENSION CONTRACT; add `jobs` + `lifecycle` namespaces, never break the existing surface.
- frontend/src/lib/api/types.ts — add Job + lifecycle types here.
- frontend/src/lib/stores/user.svelte.ts — the `.svelte.ts` rune-store convention for jobs.svelte.ts.
- frontend/src/lib/components/quotas/QuotaIndicator.svelte — the existing right-side Sheet drawer; TasksDrawer mounts beside it in AppShell; the two are mutually exclusive.
- frontend/src/lib/components/forms/ConfirmByNameDialog.svelte — Svelte 5 runes shape ($props, $bindable, $state, $derived, $effect); PowerConfirmDialog copies its structure but uses alert-dialog.

- Auto-open for clone/migrate/backup/restore only; fast power actions leave it collapsed + bump the badge.
- Job state → color: pending/claimed muted+Clock, running muted+Loader2 spin, succeeded success+CircleCheck, failed destructive+CircleAlert, orphaned warning+TriangleAlert, needs_review warning+CircleSlash. 3px left-edge tint bar.
- Count badge: 18px circle, primary when running, destructive when unacknowledged failure, hidden at 0, "9+" overflow.
- Icons (Phase 3 allow-list): Play, Square, RotateCw, Power, PowerOff, ListChecks, RefreshCw, CircleSlash, ClipboardList, Activity, Trash2, ChevronsRight, plus Phase 1+2 carry-forward (Loader2, CircleCheck, CircleAlert, TriangleAlert, Clock, MoreHorizontal, ChevronDown, ChevronRight, X, Lock).
- Elapsed format: <60s "12s", <60m "4m 12s", >=60m "1h 04m". No dayjs/luxon/date-fns.
- Confirmation matrix: Start = no dialog; Stop/Reboot/Shutdown = OK/Cancel alert-dialog; Force-Stop = destructive alert-dialog; Delete = ConfirmByNameDialog (typed-name).
- Retry button: variant="outline" size="sm", RotateCw, "Retry job"; idempotent kinds only (vm.power, vm.snapshot.delete, vm.resize, vm.backup); absent for vm.clone/vm.migrate/vm.delete/vm.restore.
- Error presentation: friendly message first, "Show technical details" collapsible (raw stderr + UPID + task log), NO redaction (D-15).
- All CTA copy in UI-SPEC §Copywriting Contract is verbatim user-facing copy.

   - `jobs = $state<Job[]>([])` — the live job list, newest-first, client-trimmed to the most recent 50 (UI-SPEC ordering rule).
   - `connected = $state(false)`, `drawerOpen = $state(false)`, `failuresAcknowledged = $state(true)`.

On `close`: set `connected=false`, schedule a reconnect with backoff; on reconnect the server re-sends `backfill` and the store reconciles by `id`. While disconnected the UI keeps elapsed timers ticking from `created_at` (the elapsed formatter is called with a live `nowMs` — see the drawer task).
   - `upsertJob(job)` — replaces or prepends by `id`; on a `succeeded`/`failed` transition, fire the completion toast (D-03 — `toast.success`/`toast.error` from svelte-sonner with the UI-SPEC copy: success `"{Action} finished for {vm-name}."`, failure `"{Action} failed for {vm-name}: {friendly error}."` sticky + an "Open in Tasks" action); auto-open the drawer for long kinds (`vm.clone`/`vm.migrate`/`vm.backup`/`vm.restore` — D-02) by setting `drawerOpen=true`.

   - `retry(id)` — calls `api.jobs.retryJob(id)`.
