Build the first full vertical slice of the job pipeline: the power lifecycle operations (Start, Stop/force, Reboot, Shutdown/graceful, Delete, plus bulk Start/Stop/Reboot), the `run_power_action` arq job function, the jobs API (`GET /jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/retry`), and the Tasks-drawer WebSocket endpoint. Purpose: Prove the entire pipeline works on the simplest operations before snapshots/backups/clone/migrate layer on.
Output: Power endpoints returning 202, the jobs API + retry, and the live WebSocket feed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → lifecycle routes | Untrusted power-action requests; CSRF + RBAC must gate every one |
| browser → WebSocket /ws/jobs | Long-lived connection; auth at handshake + per-push team filter |
| worker → Proxmox | Power dispatch as the per-team privsep token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Elevation of Privilege | Power/delete on another tenant's VM | mitigate | Every lifecycle route depends on `require_resource_access` (Phase 2 RBAC) which resolves the per-team connector and returns 403 for cross-tenant before any enqueue.
