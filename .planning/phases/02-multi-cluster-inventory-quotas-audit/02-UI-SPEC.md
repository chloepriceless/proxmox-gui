# Phase 2 — UI Design Contract

> Visual and interaction contract for Multi-Cluster Inventory, Quotas & Audit. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance rule:** This contract **extends** the Phase 1 UI-SPEC (`01-UI-SPEC.md`). The Design System, Spacing Scale, Typography, Color tokens, and Form Patterns sections of the Phase 1 spec are the source of truth and **carry forward unchanged**. This document adds Phase 2 surfaces, new component contracts (FilterChip, QuotaIndicator, ClusterSection, AuditTable, CsvExportButton, MarkdownNotes), and the icon allow-list deltas. Where Phase 2 needs a new state or pattern that Phase 1 did not cover, it is declared here explicitly.
>
> **Stack note (unchanged from Phase 1):** SvelteKit 2 + Svelte 5 + Tailwind v4 + shadcn-svelte. Toast via sonner already mounted in `AppShell.svelte` (bottom-right, richColors, closeButton).

**New shadcn-svelte blocks/components to add in Phase 2** (executor runs these in addition to the Phase 1 set):

```bash
pnpm dlx shadcn-svelte@latest add \
  scroll-area progress popover command \
  accordion collapsible
```

Rationale per block:
- `scroll-area` — bounded scroll inside the QuotaIndicator details drawer and inside long FilterChip rows on narrow viewports
- `progress` — quota usage bars in QuotaIndicator drawer + inline `/admin/teams/{id}` Quotas tab "current usage" indicator
- `popover` — Cluster-Context-Picker (replaces the Phase 1 disabled `<Select>`) and the date-range picker on `/audit`
- `command` — tag autocomplete dropdown (D-14: freeform with autocomplete from team-scope existing tags)
- `accordion` / `collapsible` — `/inventory` per-cluster collapsible sections (D-01)

**Markdown renderer for notes (D-15):** **`marked` v15.x** (lightweight, no plugin overhead, sanitises via `DOMPurify` v3 wrapper). Rationale documented under §Component Contracts §MarkdownNotes.

**Date-range picker:** **`bits-ui` `DateRangePicker` primitive** (shipped with bits-ui 2.18) — not a separate library, no third-party registry.

**CSV encoding (D-19):** **UTF-8 with BOM** (`U+FEFF` prefix, written as the bytes `0xEF 0xBB 0xBF`). Rationale: operator audience uses Excel for ad-hoc audit review; the BOM is the single byte that decides whether umlauts render as "Ãœ" or "Ü". The 3-byte cost is irrelevant against the 50000-row hard limit.

## Spacing Scale (inherited)

Inherited verbatim from Phase 1 UI-SPEC §Spacing Scale. No new tokens introduced. Phase 2 uses:

- `xs` (4px) — Filter-chip inner padding, tag-pill inner padding, sort-icon to label gap
- `sm` (8px) — Filter-chip row gap, table cell padding, status-icon to row text gap, tab trigger horizontal padding
- `md` (16px) — Form field gap (Quotas-tab table cell vertical padding, Notes editor body padding), card inner padding (top/bottom), inventory section header inner padding
- `lg` (24px) — Card inner padding (left/right), section header bottom margin, page header bottom margin, inventory section vertical gap
- `xl` (32px) — Gap between top-level sections on detail page, gap between Filter row and first inventory section
- `2xl` (48px) — QuotaIndicator details drawer outer padding, empty-state hero vertical padding
- `3xl` (64px) — Empty-state hero top margin on `/inventory` and `/audit` (Phase 1 reserved this; Phase 2 first uses it)

### Tag pill auto-derived hue (D-deferred Tag-Color-Customization)

Tag colors are auto-derived from a stable hash of the tag string. The hash maps to one of 12 palette buckets; each bucket pins a (background, border, foreground) triple drawn ONLY from existing tokens — no new tokens introduced. Implementation note:

```ts
// Pseudocode for executor
const PALETTE = [
  'bg-primary/10 border-primary/30 text-primary',
  'bg-success/10 border-success/30 text-success',
  'bg-warning/10 border-warning/30 text-warning',
  'bg-destructive/10 border-destructive/30 text-destructive',
  // 8 more: variations on muted + foreground combos to avoid pulling new tokens
  'bg-muted border-border text-foreground',
  // ... see §Component Contracts §TagPill for the full table
];
```

Full palette table is in §Component Contracts §TagPill. The deliberate constraint: **a tag color is NEVER the dominant signal** (status icon + text label always co-present per the a11y floor — UI-SPEC §Accessibility "no information by color alone").

**Page-header contract:**
- Title `Display 28/600`, description `Body 14/400 text-muted-foreground`
- No primary CTA on this page (creation is Phase 4); rightmost area of header row is empty

**Filter row contract (sticky):**
- `position: sticky; top: 56px (Topbar)`, `bg-background`, bottom border 1px `--border`, 16px (md) vertical padding inside
- Row 1: search input (flex-1) + sort dropdown (`Sort ▾`)
- Row 2 (only when filters active): FilterChip pills + "Clear all" link (`Button variant="link"`)
- Sort dropdown options (D-05): "Status (default)", "Name A→Z", "VMID", "Last changed"; selection is **not persisted** — every page-load resets to "Status (default)"

**Cluster section contract (D-01, D-03, D-06):**
- When `clusters.length === 1`: section header **hidden**, only the row table renders (flat list)
- When `clusters.length >= 2`: each cluster is one collapsible `<Accordion.Item>` (shadcn-svelte block)
- Section header bar: 48px tall, `bg-muted/40`, click toggles expand/collapse, contains:
  - Left: ChevronDown (rotates 0/-90deg per state), cluster name (Heading 18/600), ClusterStatusPill (reuse Phase 1 component)
  - Right: counter badge — `(N)` when unfiltered, `(N matches / N total)` when any filter is active per D-06
- Default state: **expanded** (every section opens on page load)
- Filter empties section → section stays visible, body still rendered as an empty-list message `"No VMs match the current filter in this cluster."`
- Unreachable cluster (D-03): a 56px-tall banner `Alert variant="destructive"` slots **between** the section header and the row table; body shows last-cached rows; every row gets a `Stale` badge (Label 13/500, warning palette, `Clock` icon)

**Row contract:**
- 56px tall (`h-14`), padding `lg` (24px) horizontal, `md` (16px) vertical inside, hover background `--muted`, click → navigate to `/inventory/{cluster_id}/{vmid}`
- Columns left-to-right:
  1. Status icon (16px) + status label (Body 14/400, e.g. "running" / "stopped"; see Color §VM status table)
  2. Name (Body 14/400) + vmid (Mono 13/400 muted, below name)
  3. Tags (TagPill component, up to 3; if more, "+N" pill linking to detail page Overview tab)
  4. Node (Body 14/400 muted)
  5. Right-aligned: `ChevronRight` (16px, muted) — affordance for the row being clickable
- Selected/focused state: `bg-primary/5 + border-l-2 border-l-primary` (matches Phase 1 data-table selected state)

**Default sort within section (D-05):** primary by status-priority (running → stopped → paused → error → unknown), secondary by name A→Z. User can re-sort via header dropdown; choice does NOT persist (no localStorage).

- Row click → inline expand revealing before/after diff (`Card` slot, 16px padding, Mono 13/400)
- Diff renderer: side-by-side OR unified — **executor picks unified** (single-column, simpler at narrow viewports, fewer line-shift bugs); diff syntax `[-removed-] [+added+]` with `--destructive` background tint for removed-line `--success` for added-line
- Pagination: page size 50 (Phase 1 data-table default); pager footer with prev/next + total count
- Empty state copy: "No audit entries match the current filters." (no illustration; clean empty pane)

└──────────────────────────────────────────────────────────────────────┘

**Quotas tab contract:**
- One row per cluster the team is bound to (= one row per `cluster_id` that has a quota record for this team)
- Columns: Cluster name (sticky-left), vCPU (number input min=0, step=1), RAM GB (number), Disk GB (number), VM count (number)
- Below each row, a single-line muted **current usage** read-out (D-09 — read-only summary derived from live PVE inventory); shows utilization % with the same 80%/95% color rules (D-10) — text turns yellow ≥80%, red ≥95%

- If admin tries to **lower** a limit below current usage: dialog `Alert variant="warning"` blocks save with "Current usage 14 vCPU exceeds the new limit 8 vCPU. Free up resources first or raise the limit." (D-12: no override)
- Save → triggers audit-log entry (action=quota.update with before/after diff per AUDIT-02)

## Accessibility Floor (inherited + extensions)

The Phase 1 a11y floor (keyboard reach, focus rings, aria-labels on icon-only buttons, status-via-icon-AND-text, skip-to-content) carries forward. Phase 2 additions:

- **Collapsible sections:** `aria-expanded` on the header button; `aria-controls` linking header to body region
- **Tab strip:** `role="tablist"` on the strip, `role="tab"` + `aria-selected` + `aria-controls` per trigger, `role="tabpanel"` + `aria-labelledby` per panel — bits-ui handles this in the `tabs` block
- **FilterChip remove buttons:** `aria-label="Remove filter {label}"`
- **Tag pills:** `aria-label="Tag {tag}"` on clickable variants (in inventory rows for filter-add)
- **Quota indicator block:** `aria-label="Quota: {X} of {Y} CPU, {A} of {B} RAM. Click for details."` plus `aria-live="polite"` on the numeric values so screen readers announce updates
- **Quota warning toasts:** sonner toasts already announce via `aria-live` — verified
- **Audit table row expand:** `aria-expanded` + `aria-controls` on the row; expanded diff has `role="region"` + `aria-label="Before-after diff for {action}"`
- **Cluster unreachable banner:** `role="alert" aria-live="assertive"` so screen readers announce the degraded state immediately

## Implementation Notes for Executor

1. **Cluster-Context-Picker first.** Activate the Phase 1 disabled `<Select>` placeholder by replacing it with the new `ClusterContextPicker` component. Every other Phase 2 surface depends on this.
2. **QuotaIndicator mounts before any inventory work** so its localStorage warning-fired state is established when the user first navigates.
3. **Per-page `+page.server.ts` defence-in-depth auth gates** (Phase 1 pattern) on every new route — `/inventory`, `/inventory/{cluster_id}/{vmid}`, `/audit`. Each re-checks `event.locals.user` and redirects to `/login` if missing.
4. **URL-as-state for filters (D-04).** Filter state is the URL — no client-side filter store. The page-server-load reads URL params and passes them to the API. Browser back/forward works for free.
5. **`$derived(localOverride ?? data.list)` (Plan 01-09 pattern)** for optimistic Tag adds/removes and Notes saves. SSR seed from page load, post-mutate UX via override.
6. **Markdown sanitization is non-negotiable.** `DOMPurify` wraps every `marked.parse(…)` call. Unit test asserts XSS payload is stripped.
7. **CSV BOM placement is the first byte of the response body** — not after `Content-Type`. Verify with `xxd -l 16 export.csv` showing `efbb bf` as bytes 0–2.
8. **The "Show team actions" toggle is a server-side filter.** The client cannot grant itself team-action visibility — the server checks each row against the user's team memberships regardless of the toggle.
9. **The 50000-row export cap is enforced server-side** with a hard `LIMIT 50001` on the SELECT — if the 50001st row exists, the response is `409 Conflict` with a `Too many rows; refine filter` body, mapped to the disabled-button tooltip on the client.
10. **Sparklines are hand-rolled SVG** — do NOT import a chart library. The bundle-size argument is recorded; future phases may revisit if the team needs richer charts.
11. **The 30-second stale-cache TTL (ROADMAP)** is a connector-impl detail — UI just renders `stale` when the API returns `data.is_stale === true`. The Researcher is not pinning the exact TTL here; the connector module owns it.
12. **All copy in this contract is the user-facing copy** — executor uses it verbatim. Changes require updating this spec, not silently in code.
13. **The Phase 1 ClusterStatusPill component is extended in-place** with a new `stale` state — do not create a separate component. The single source of truth for cluster connection-status visualization is the existing pill.
14. **The Activity tab is the same `AuditTable` component as `/audit`** — props vary only in the `lockedFilters` prop. Do not fork the component.
