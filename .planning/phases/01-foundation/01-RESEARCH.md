# Phase 1: Foundation - Research

**Researched:** 2026-05-14
**Domain:** FastAPI modular monolith scaffold + multi-tenant SQLite schema + local auth (Argon2id sessions + PATs) + per-cluster encrypted token storage + OpenAPI-backed REST shell + SvelteKit UI skeleton + first-run installer
**Confidence:** HIGH (all primary decisions locked in CONTEXT.md; stack verified against current PyPI/npm; one MEDIUM area called out: proxmoxer ↔ asyncio bridge)

## Summary

Phase 1 establishes every pattern subsequent phases will reuse: the FastAPI app factory, async SQLAlchemy session DI, the Alembic baseline (revision `0001_initial`), the Fernet-wrapped secret type for encrypted columns, the per-cluster connector primitive (placeholder shape only — full implementation in Phase 2), the shadcn-svelte component vocabulary, and the helper-script LXC packaging skeleton. Nothing in this phase is exploratory: CONTEXT.md locks 19 decisions (D-01 through D-19) and the discuss-phase already settled every architectural fork worth settling. Research's job is to make those decisions concrete and prescriptive so the planner can write task-level plans without re-deriving anything.

The two technical bridges that warrant verification: (1) proxmoxer 2.3.0 remains synchronous (no async backend landed), so every PVE call must go through `await asyncio.to_thread(...)` — this is foundational stack glue, not optional; (2) the cookie-auth + PAT-auth dual-mode pattern in FastAPI must resolve through a single `get_current_principal()` dependency that distinguishes the two paths cleanly, because PATs skip CSRF (D-13) and cookies require it.

**Primary recommendation:** Build the seven foundational primitives (app factory, async session, Fernet column type, JWT issuer, dual-mode auth dependency, cluster registry stub, Alembic baseline) as plain, well-tested modules in `app/core/` *before* writing any route handler. Every route will reuse these — getting them right once is the whole game.

## User Constraints (from CONTEXT.md)

### Locked Decisions

**Tenant ↔ Proxmox Auth:**
- **D-01:** Per-tenant privilege-separated PVE tokens. Each app-tenant (team) maps to a PVE user + pool + privilege-separated API token. Proxmox enforces ACLs natively.
- **D-02:** Auto-bootstrap on tenant create. Backend creates the PVE user, pool, and privilege-separated token on every registered cluster when admin creates a team. Failure on any cluster blocks team creation (transactional across DB + PVE; rollback on partial failure).
- **D-03:** Cluster-registration token is Administrator-level (`User.Modify`, `Pool.Allocate`, `Realm.Allocate`, `Sys.Audit` at `/`). Encrypted at rest, used for both tenant provisioning and runtime ops in v1.
- **D-04:** Tenant delete blocked when tenant owns VMs/LXCs. No cascade-delete of PVE objects. "Disabled" state blocks logins/API use, leaves PVE-side intact.

**Tenancy & Ownership Model:**
- **D-05:** Team is the primary tenant boundary. Every user has an auto-created **personal team** (immutable name/membership) plus may belong to N **shared teams**. Many-to-many user↔team.
- **D-06:** One PVE pool per team. Personal teams get their own pool too.
- **D-07:** Resource ownership is team-level. VMs/LXCs hang off `team_id`; every member is an equal editor in v1. `created_by_user_id` is informational/audit only.
- **D-08:** **Quota math:** Per-team quota applies when user is in any shared team(s); per-user quota ignored in that case. Per-user quota enforced ONLY when user is solo in their personal team.

**Sessions:**
- **D-09:** httpOnly + Secure + SameSite=Lax cookies. Both access JWT and refresh token. JS never touches them.
- **D-10:** Access JWT TTL: 15 minutes. Refresh TTL: 7 days. Refresh rotates on every use.
- **D-11:** Refresh tokens DB-stored (encrypted/hashed) for server-side revocation. AUTH-07 disable-user must invalidate live refresh tokens immediately.

**PATs:**
- **D-12:** `Authorization: Bearer <token>` header. Distinguished from session JWT by token prefix or table lookup. Inherits user's tenants + role exactly. Config: name + optional expiry. Token shown once. Revocation UI in per-user Tokens settings.

**CSRF:**
- **D-13:** Double-submit cookie + SameSite=Lax. JS-readable CSRF cookie echoed via `X-CSRF-Token` header on state-changing cookie-session requests. Bearer-PAT calls skip CSRF.

**Encryption:**
- **D-14:** Master key generated by installer: 32 bytes random at `/etc/proxmox-gui/master.key`, mode 0600, owned by service user. Part of self-backup (Pitfall 22).
- **D-15:** Symmetric crypto = **Fernet** (`cryptography` library). Used for per-cluster PVE tokens at rest, DB-stored refresh tokens, PAT-secret pepper.

**Wizard + Packaging:**
- **D-16:** LXC base OS: **Debian 12 (Bookworm)**. Python 3.12 install approach is Claude's discretion.
- **D-17:** Three systemd units: `proxmox-gui-api.service` (FastAPI/uvicorn), `proxmox-gui-worker.service` (arq), `caddy.service`. LXC requires `nesting=1`. Logs to journald.
- **D-18:** First-run validation is **lenient**. Only initial admin user mandatory. Cluster registration and SSH key optional in the wizard; post-install banner surfaces "add a cluster".
- **D-19:** Wizard UX is a **multi-step stepper** (3–4 steps): Welcome → Create admin → Register first cluster (skippable) → Done.

## Architectural Responsibility Map

| Capability | Primary Tier | Secondary Tier | Rationale |
|---|---|---|---|
| Password hashing & verification | API/Backend | — | Secrets never leave the server; argon2 is server-only. |
| JWT issue & verify | API/Backend | — | Signing key is server-side. |
| Session cookie set/clear | API/Backend (writes `Set-Cookie`) | Browser (stores cookie) | Browser stores; server controls policy and rotation. |
| CSRF token | API/Backend (mints token, validates header) | Frontend SSR (echoes cookie → header) | Server is the only validator; SvelteKit reads JS-readable cookie. |
| PVE API call | API/Backend | — | Token MUST NOT touch the browser. Worker (Phase 3) too. |
| Fernet encrypt/decrypt | API/Backend | — | Master key file is server-only. |
| Schema migrations | API/Backend (on boot) | — | Alembic runs in the API process at startup. |
| Static asset serving | CDN/Static (Caddy) | — | Caddy serves `/` SvelteKit build; FastAPI handles `/api/*` only. |
| OpenAPI spec generation | API/Backend | — | FastAPI introspects pydantic schemas. |
| Theme persistence | Browser (localStorage + class on `<html>`) | Frontend SSR | Pure client concern; server has nothing to do with theme. |
| Form validation | Frontend (client-side) + API/Backend (authoritative) | — | UI hints early; server is the only trusted check. |
| Reverse-proxy TLS | CDN/Static (Caddy) | — | Caddy auto-HTTPS; FastAPI listens plain on 127.0.0.1. |
| First-run wizard state | Frontend (transient stepper) + API/Backend (admin existence check) | — | Server gates the wizard via "no admin yet" predicate. |

**Cross-cutting check:** No business logic lives in the browser. SvelteKit is a render + UX layer; every authority decision is server-side. CONTEXT D-07 ("equal editors") means RBAC checks are minimal in Phase 1 — just "is user a member of the team that owns this resource?" — but the check still lives in FastAPI dependencies, not in Svelte components.

### Pattern 1: FastAPI App Factory + Lifespan

**What:** A single `create_app()` function returns a configured FastAPI app. Boot-time concerns (migrate DB, load master key, build connector registry) run in the lifespan.

**Why:** Testable (different configs per test), single source of truth for middleware order, and the lifespan is the only safe place to do async I/O at startup (e.g., load master key, run `alembic upgrade head`).

```python
# app/main.py
from contextlib import asynccontextmanager

from fastapi.middleware.cors import CORSMiddleware
from app.config import settings
from app.core.db import engine, run_migrations
from app.core.cipher import SecretCipher
from app.clusters.registry import PVEConnectorRegistry
from app.auth.routes import router as auth_router
from app.users.routes import router as users_router
# ... other routers


@asynccontextmanager
async def lifespan(app: FastAPI):
    # boot
    app.state.cipher = SecretCipher.from_file(settings.master_key_path)
    await run_migrations()
    app.state.registry = PVEConnectorRegistry(app.state.cipher)
    # connectors are lazy; registry just holds the cipher + DB session factory

    # shutdown
    await engine.dispose()


def create_app() -> FastAPI:

    app.include_router(users_router, prefix="/api/v1", tags=["users"])
    # ... etc
```

### Pattern 3: Fernet-wrapped Encrypted Column

**What:** A `SecretCipher` singleton (loaded once from `/etc/proxmox-gui/master.key`) plus a SQLAlchemy `TypeDecorator` that transparently encrypts on write and decrypts on read.

```python
# app/core/cipher.py
from pathlib import Path
from cryptography.fernet import Fernet
import base64

class SecretCipher:
    def __init__(self, key_bytes: bytes):
        # Fernet wants url-safe base64. master.key is raw 32 bytes; derive a
        # Fernet key from it deterministically.
        fernet_key = base64.urlsafe_b64encode(key_bytes)
        self._fernet = Fernet(fernet_key)

    @classmethod
    def from_file(cls, path: Path) -> "SecretCipher":
        raw = path.read_bytes()
        if len(raw) != 32:
            raise ValueError(f"master.key must be exactly 32 bytes, got {len(raw)}")
        return cls(raw)

    def encrypt(self, plaintext: str) -> bytes:
        return self._fernet.encrypt(plaintext.encode("utf-8"))

    def decrypt(self, ciphertext: bytes) -> str:
        return self._fernet.decrypt(ciphertext).decode("utf-8")


# app/models/_types.py
from sqlalchemy.types import TypeDecorator, LargeBinary

class EncryptedSecret(TypeDecorator):
    """Stores a string encrypted at rest using the app's master cipher.

    Reads `app.state.cipher` at process_bind/process_result time via a
    module-level accessor — see _types_init.py.
    """
    impl = LargeBinary
    cache_ok = True

    def process_bind_param(self, value, dialect):
        if value is None:
            return None
        return _get_cipher().encrypt(value)

    def process_result_value(self, value, dialect):
        if value is None:
            return None
        return _get_cipher().decrypt(value)
```

**Critical gotcha:** SQLAlchemy `TypeDecorator` is called outside request context, so we can't grab the cipher from `request.app.state`. Use a module-level `_cipher_ref` injected at app startup:

```python
# app/models/_types_init.py
_cipher = None
def install_cipher(cipher): global _cipher; _cipher = cipher
def _get_cipher(): 
    if _cipher is None: raise RuntimeError("cipher not installed")
    return _cipher
```

Call `install_cipher(app.state.cipher)` in lifespan after loading the key. [CITED: docs.sqlalchemy.org/en/20/core/custom_types.html#sqlalchemy.types.TypeDecorator]

### Pattern 4: Dual-Mode Auth (Cookie OR Bearer PAT)

**What:** A single `get_current_principal()` dependency that handles both authenticated paths. CSRF check is layered on top via a separate dependency that's a no-op for PAT-authenticated requests.

```python
# app/auth/dependencies.py
from typing import Optional
from fastapi import Depends, HTTPException, Request, status
from sqlalchemy.ext.asyncio import AsyncSession
from app.core.db import get_db
from app.core.jwt import decode_access_token
from app.models.user import User
from app.models.pat import PersonalAccessToken
from sqlalchemy import select

PAT_PREFIX = "pat_"  # token format: pat_<24 random b32> ; lookup-key on first 12

class Principal:
    """Represents an authenticated user + the mode they used."""
    def __init__(self, user: User, mode: str):
        self.user = user
        self.mode = mode  # "session" | "pat"

    @property
    def via_pat(self) -> bool:
        return self.mode == "pat"


async def get_current_principal(
    request: Request,
    db: AsyncSession = Depends(get_db),
) -> Principal:
    # 1. Bearer PAT takes precedence (explicit > implicit)
    auth = request.headers.get("Authorization", "")
    if auth.startswith("Bearer "):
        token = auth.removeprefix("Bearer ").strip()
        if token.startswith(PAT_PREFIX):
            user = await _resolve_pat(db, token)
            if user is None:
                raise HTTPException(401, "Invalid PAT")
            return Principal(user, mode="pat")
        # else: not our token format; fall through to cookie

    # 2. Session cookie
    access = request.cookies.get("access_token")
    if access:
        try:
            payload = decode_access_token(access)
        except Exception:
            raise HTTPException(401, "Invalid or expired session")
        user = await db.get(User, payload["sub"])
        if user is None or not user.is_active:
            raise HTTPException(401, "User not found or disabled")
        return Principal(user, mode="session")

    raise HTTPException(401, "Not authenticated")


async def require_admin(principal: Principal = Depends(get_current_principal)) -> Principal:
    if not principal.user.is_admin:
        raise HTTPException(403, "Admin required")
    return principal


async def csrf_protect(
    request: Request,
    principal: Principal = Depends(get_current_principal),
) -> None:
    if principal.via_pat:
        return  # D-13: PATs skip CSRF
    if request.method in {"GET", "HEAD", "OPTIONS"}:
        return
    csrf_cookie = request.cookies.get("csrf_token")
    csrf_header = request.headers.get("X-CSRF-Token")
    if not csrf_cookie or not csrf_header or csrf_cookie != csrf_header:
        raise HTTPException(403, "CSRF check failed")
```

**Why this works:** PAT detection by prefix avoids a DB lookup on every cookie-auth request. CSRF is applied as a separate dependency so handlers opt in explicitly (`Depends(csrf_protect)`) or via a router-wide dep. [CITED: fastapi.tiangolo.com/tutorial/dependencies/]

### Pattern 5: JWT Issuance + DB-Stored Refresh Tokens

**What:** Access tokens are stateless JWTs (15-min TTL); refresh tokens are random opaque values, stored hashed in `refresh_tokens` table, single-use (rotate on every refresh). The PAT pepper from D-15 is a Fernet-encrypted column too, used to make PAT lookup constant-time-ish via prefix indexing.

```python
# app/core/jwt.py
import jwt
from datetime import datetime, timedelta, timezone
from uuid import uuid4
from app.config import settings

ALG = "HS256"

def issue_access_token(user_id: int, *, is_admin: bool) -> str:
    now = datetime.now(timezone.utc)
    payload = {
        "sub": str(user_id),
        "adm": is_admin,
        "iat": int(now.timestamp()),
        "exp": int((now + timedelta(minutes=15)).timestamp()),
        "jti": str(uuid4()),
        "iss": "proxmox-gui",
    }
    return jwt.encode(payload, settings.jwt_secret, algorithm=ALG)


def decode_access_token(token: str) -> dict:
    return jwt.decode(
        token,
        settings.jwt_secret,
        algorithms=[ALG],
        options={"require": ["exp", "sub", "iat"]},
    )
```

**Refresh token shape:**
- `refresh_tokens.id` (PK, integer)
- `user_id` (FK)
- `token_hash` (sha256 of the secret) — looked up directly
- `expires_at`
- `revoked_at` (nullable)
- `replaced_by_id` (FK self; for rotation audit)
- `user_agent`, `ip_address` (for the user's "active sessions" page later)

Rotation flow:
1. Client sends refresh cookie.
2. Server hashes it, looks up row. If row missing / revoked / expired → 401, force re-login.
3. **If `replaced_by_id` is non-null when the row is presented again, this is replay** — revoke the entire chain (security alarm), force re-login.
4. Else: mint new access + new refresh, mark old row `revoked_at=now`, `replaced_by_id=new_id`, set new cookies.

[CITED: PyJWT docs at pyjwt.readthedocs.io/en/stable/usage.html; refresh rotation pattern from Auth0 blog "Refresh Token Rotation"]

### Pattern 6: PAT Format and Storage

**What:** PATs are `pat_<24 random base32 chars>`. The first 12 chars (after the prefix) are stored unencrypted in the DB as `lookup_prefix` (indexed). The full token's SHA-256 is stored as `token_hash`. The pepper from D-15 is a server-secret mixed into the hash to thwart rainbow attacks.

```python
# app/pats/service.py
import secrets
import hashlib
from app.config import settings

def mint_pat() -> tuple[str, str, str]:
    """Returns (plaintext_token, lookup_prefix, token_hash)."""
    body = secrets.token_urlsafe(18)  # 24 chars base64url
    token = f"pat_{body}"
    lookup_prefix = body[:12]
    h = hashlib.sha256()
    h.update(settings.pat_pepper.encode("utf-8"))
    h.update(token.encode("utf-8"))
    return token, lookup_prefix, h.hexdigest()


async def resolve_pat(db, token: str):
    if not token.startswith("pat_"):
        return None
    body = token[4:]
    lookup_prefix = body[:12]
    rows = await db.execute(
        select(PersonalAccessToken).where(PersonalAccessToken.lookup_prefix == lookup_prefix)
    )
    candidates = rows.scalars().all()
    h = hashlib.sha256()
    h.update(settings.pat_pepper.encode("utf-8"))
    h.update(token.encode("utf-8"))
    target_hash = h.hexdigest()
    for c in candidates:
        if c.revoked_at: continue
        if c.expires_at and c.expires_at < datetime.now(timezone.utc): continue
        if secrets.compare_digest(c.token_hash, target_hash):
            return c.user
    return None
```

**Rationale:** Full SHA-256 lookup would require either a unique index (fine) or a table scan. With the 12-char prefix as an indexed column, we narrow to typically one row, then constant-time compare. This is the same trick GitHub uses for PATs (`ghp_*` prefix + opaque body).

### Pattern 7: PVE Connector (Phase 1 Placeholder Shape)

**What:** In Phase 1 we only need the connector to (a) validate a cluster's API token on registration, and (b) bootstrap a tenant (create PVE user + pool + token via D-02). Circuit breaker, caching, and the full read API land in Phase 2/3. But the *shape* is set here.

```python
# app/clusters/connector.py
from proxmoxer import ProxmoxAPI
import asyncio
from typing import Any

class PVEConnector:
    """Per-cluster Proxmox API client wrapper.

    Wraps the synchronous `proxmoxer` library with `asyncio.to_thread()`.
    Phase 1 scope: validate_token, bootstrap_tenant.
    Phase 2: read endpoints + circuit breaker + cache.
    Phase 3: write endpoints + UPID polling integration.
    """

    def __init__(
        self,
        host: str,
        port: int,
        token_user: str,        # e.g. "root@pam"
        token_name: str,        # e.g. "gui-bootstrap"
        token_value: str,       # the secret
        verify_ssl: bool,
    ):
        self._client = ProxmoxAPI(
            host,
            port=port,
            user=token_user,
            token_name=token_name,
            token_value=token_value,
            verify_ssl=verify_ssl,
            timeout=10,
        )

    async def _call(self, fn, *args, **kwargs) -> Any:
        # proxmoxer 2.3 has no async backend; bridge through default executor.
        return await asyncio.to_thread(fn, *args, **kwargs)

    async def version(self) -> dict:
        return await self._call(self._client.version.get)

    async def validate(self) -> None:
        """Raises if the token can't reach /version."""
        await self.version()

    async def create_pool(self, poolid: str, comment: str = "") -> None:
        await self._call(self._client.pools.post, poolid=poolid, comment=comment)

    async def create_user(self, userid: str, comment: str = "") -> None:
        await self._call(self._client.access.users.post, userid=userid, comment=comment)

    async def create_token(
        self, userid: str, tokenid: str, *, privsep: bool = True
    ) -> dict:
        # Returns {"value": "<secret>", "info": {...}}
        return await self._call(
            self._client.access.users(userid).token(tokenid).post,
            privsep=int(privsep),
        )

    async def set_pool_acl(self, poolid: str, *, userid: str, role: str) -> None:
        await self._call(
            self._client.access.acl.put,
            path=f"/pool/{poolid}",
            users=userid,
            roles=role,
            propagate=1,
        )

    async def delete_user(self, userid: str) -> None:
        await self._call(self._client.access.users(userid).delete)

    async def delete_pool(self, poolid: str) -> None:
        await self._call(self._client.pools(poolid).delete)
```

**Authorization format** (CONFIRMED by Proxmox wiki): `Authorization: PVEAPIToken=USER@REALM!TOKENID=UUID`. proxmoxer builds this automatically from `user=...`, `token_name=...`, `token_value=...`.

```python
# app/clusters/registry.py
class PVEConnectorRegistry:
    """Builds & caches connectors keyed by cluster_id."""
    def __init__(self, cipher: SecretCipher, session_factory):
        self._cipher = cipher
        self._session_factory = session_factory
        self._connectors: dict[int, PVEConnector] = {}

    async def get(self, cluster_id: int) -> PVEConnector:
        if cluster_id not in self._connectors:
            async with self._session_factory() as db:
                row = await db.get(Cluster, cluster_id)
                if row is None:
                    raise LookupError(f"cluster {cluster_id} not found")
                # row.api_token_secret was decrypted by EncryptedSecret TypeDecorator
                self._connectors[cluster_id] = PVEConnector(
                    host=row.host, port=row.port,
                    token_user=row.token_user,
                    token_name=row.token_name,
                    token_value=row.api_token_secret,
                    verify_ssl=row.verify_ssl,
                )
        return self._connectors[cluster_id]

    def invalidate(self, cluster_id: int) -> None:
        self._connectors.pop(cluster_id, None)
```

### Pattern 8: Tenant Bootstrap on Team Create (D-02)

**What:** When admin creates a team, we transactionally create:
1. App-side team row (with `personal=False`)
2. On every registered cluster: `gui-team-<id>` pool, `gui-team-<id>@pve` user, `gui-team-<id>!api` privilege-separated token with `PVEVMUser` role on `/pool/gui-team-<id>`
3. Store each per-cluster token (Fernet-encrypted) in `team_cluster_tokens` table

If any cluster bootstrap fails, roll back: delete user (best-effort) on cluster(s) where partial state exists, delete team row, return 500. Surfaces the failing cluster name.

```python
# app/teams/service.py (sketch)
async def create_team(db, registry, name: str, admin_user: User) -> Team:
    # 1. allocate team_id
    team = Team(name=name, personal=False)
    db.add(team)
    await db.flush()  # get team.id

    bootstrap_state = {}  # cluster_id -> {"user": bool, "pool": bool, "token": dict|None}

    try:
        clusters = (await db.execute(select(Cluster).where(Cluster.is_active == True))).scalars().all()
        for cluster in clusters:
            conn = await registry.get(cluster.id)
            poolid = f"gui-team-{team.id}"
            userid = f"gui-team-{team.id}@pve"
            tokenid = "api"

            await conn.create_pool(poolid, comment=f"GUI tenant {name}")
            bootstrap_state[cluster.id] = {"pool": True, "user": False, "token": None}

            await conn.create_user(userid, comment=f"GUI tenant {name}")
            bootstrap_state[cluster.id]["user"] = True

            token = await conn.create_token(userid, tokenid, privsep=True)
            bootstrap_state[cluster.id]["token"] = token

            await conn.set_pool_acl(poolid, userid=userid, role="PVEVMUser")

            db.add(TeamClusterToken(
                team_id=team.id, cluster_id=cluster.id,
                userid=userid, tokenid=tokenid,
                token_secret=token["value"],  # EncryptedSecret column
            ))

        await db.commit()
        return team

    except Exception as e:
        await db.rollback()
        # best-effort PVE cleanup of half-bootstrapped clusters
        for cluster_id, state in bootstrap_state.items():
            conn = await registry.get(cluster_id)
            poolid = f"gui-team-{team.id}"
            userid = f"gui-team-{team.id}@pve"
            try:
                if state["user"]:
                    await conn.delete_user(userid)
                if state["pool"]:
                    await conn.delete_pool(poolid)
            except Exception:
                pass  # log but don't mask original error
        raise
```

### Pattern 9: First-Run Gate

### Pattern 11: Caddy Single-Origin Reverse Proxy

**What:** Caddy listens on `:443` (auto-HTTPS for public installs, internal-CA or self-signed for LAN). Routes `/api/*` to FastAPI on `127.0.0.1:8000`; everything else to SvelteKit's adapter-node on `127.0.0.1:3000`. Single origin means no CORS, simple cookies, no Caddy CORS headache.

```
    # SvelteKit (adapter-node serves static + SSR)
    handle {

    }
}
```

For LAN-only installs (no public DNS), use:
```

    tls internal
    # ... same as above
}
```
Caddy's `tls internal` issues self-signed certs from a Caddy-managed local CA. [CITED: caddyserver.com/docs/caddyfile/options#local-certs]

### Anti-Patterns to Avoid

- **Storing the access JWT in localStorage** — defeats httpOnly. D-09 locks cookies.
- **Putting `tenant_id` only on top-level tables** — denormalize down. Every row that can be cross-tenant-queried needs it. We use `team_id` (= tenant_id from D-05).
- **Forgetting `render_as_batch=True` in Alembic env.py** — SQLite can't ALTER COLUMN; Alembic emulates via table-rebuild only when batch mode is on. Add to `env.py` from day one.
- **Auto-renaming the personal team if user is renamed** — D-05 says immutable. Pick a name format that doesn't depend on username (`personal-<user_id>` rather than `<username>-personal`). [REVISES the sketch above.]
- **Single connector instance shared across clusters** — anti-Pattern 5 in ARCHITECTURE.md. We use per-cluster connector + registry.
- **Mixing CSRF on PAT routes** — D-13 explicit: PATs bypass. The `csrf_protect` dependency must check `principal.via_pat`.
- **Letting Alembic auto-generate without review** — autogenerate is a starting point; always review the `op.create_table` for `tenant_id` presence and FK cascade behavior.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---|---|---|---|
| Password hashing | Custom Argon2 wrapping | `pwdlib[argon2]` (PasswordHash.recommended()) | Constant-time verify, parameter migration, salt handling — all baked in |
| JWT encode/decode | Custom signing | `PyJWT` 2.12+ | Vulnerable algorithm-confusion bugs in hand-rolled code; PyJWT enforces `algorithms=[...]` |
| Symmetric encryption | Raw `cryptography.hazmat.primitives` | `cryptography.fernet.Fernet` | Fernet is opinionated: AES-128-CBC + HMAC-SHA256 + version byte + timestamp. No room to misuse. |
| CSRF token gen | Time-based or HMAC-of-session | `secrets.token_urlsafe(32)` per session, stored in JS-readable cookie | Double-submit pattern is well-understood; HMAC-of-session leaks if the secret rotates |
| Session storage | Server-side session table | Stateless JWT (access) + DB-stored opaque refresh | Refresh-with-rotation gives revocation without the JWT blacklist anti-pattern |
| SSH public key parsing | Regex | `cryptography.hazmat.primitives.serialization.load_ssh_public_key` | Many edge cases (RSA bits, ed25519, ecdsa curves, options prefix). Library handles all. |
| OpenAPI generation | Hand-write JSON | FastAPI auto-generation from pydantic | Stays in sync with code; openapi-ts then generates the TS client |
| Theme toggle | Custom CSS variables | Tailwind v4 `dark:` variants + `class` strategy | First-class support; shadcn-svelte themes are built on this |
| Component primitives | Custom Dialog / Combobox | shadcn-svelte (uses bits-ui underneath) | Accessibility is non-trivial; bits-ui is Radix-quality |
| Alembic env.py | Custom migration runner | Standard Alembic with `render_as_batch=True` | SQLite ALTER limitations are the trap; batch mode handles them |
| Refresh-token chain replay detection | Ad-hoc invalidation | The `replaced_by_id` self-FK pattern | Forces O(1) detection at refresh time without sweeping |
| LXC bootstrap | bespoke shell tangle | `pct create` from helper-script + lean install script | community-scripts repo has the pattern; we just reuse the structure |
| systemd unit generation | Custom templating | Three hand-written unit files committed to `deploy/systemd/` | They never need to vary per install in Phase 1 |
| Caddy config | Programmatic generation | Single `Caddyfile.template` with `$PUBLIC_HOSTNAME` substitution | Caddy auto-HTTPS handles the dynamic part |

**Key insight:** This phase is foundation, not innovation. Every primitive listed above has a "right answer" that's been settled by the wider ecosystem. Wins come from picking the boring path consistently.

## Common Pitfalls

### Pitfall A1: SQLite ALTER COLUMN without batch mode

**What goes wrong:** Alembic generates `op.alter_column(...)` which SQLite doesn't support. Migration crashes.
**Why it happens:** SQLite only added partial ALTER in 3.35+; many operations still need table-rebuild. Alembic supports it via `with batch_alter_table(...)`, gated by `render_as_batch=True`.
**How to avoid:** In `alembic/env.py`:
```python
def do_run_migrations(connection):
    context.configure(
        connection=connection,
        target_metadata=target_metadata,
        render_as_batch=True,           # MANDATORY for SQLite
        compare_type=True,
    )
    with context.begin_transaction():
        context.run_migrations()
```
**Warning signs:** First post-initial migration that drops/renames a column crashes on `pytest`.
[CITED: alembic.sqlalchemy.org/en/latest/batch.html]

### Pitfall A2: aiosqlite + `expire_on_commit=True`

**What goes wrong:** After `await session.commit()`, accessing any ORM attribute triggers a lazy reload — which is implicit I/O — and crashes under asyncio's "concurrent operation already in progress."
**How to avoid:** Set `expire_on_commit=False` on the `async_sessionmaker` (shown in Pattern 2). [CITED: docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html]

### Pitfall A3: proxmoxer blocking the event loop

**What goes wrong:** A direct `proxmoxer.cluster.resources.get()` call inside an async handler blocks the event loop for the full HTTP latency to PVE — kills WebSocket fan-out (Phase 3+) and serializes concurrent requests.
**How to avoid:** Wrap every proxmoxer call in `await asyncio.to_thread(...)`. The `PVEConnector._call()` helper in Pattern 7 enforces this. **Lint rule** (optional): forbid bare `self._client.<x>.get()` outside `_call`.
[VERIFIED: STACK.md + github.com/proxmoxer/proxmoxer — no async backend]

### Pitfall A4: PVE token registration vs validation race

**What goes wrong:** Admin pastes a new cluster's token. The `clusters.create` route stores it, returns 201, and the admin clicks "test connection" — which fails. Token was wrong or expired.
**How to avoid:** Validate the token *before* persisting. Order in the service: instantiate connector → call `validate()` → if it fails, return 422 with PVE error message → only on success, encrypt and write the row. The "test connection" button then re-validates an already-stored cluster.

### Pitfall A5: Forgetting `team_id` on a new table

**What goes wrong:** Phase 2+ table added without a `team_id` FK because "this is admin-only." Six months later we need to scope it and have a data migration nightmare.
**How to avoid:** Every business-data table (excluding `clusters`, `users` themselves, audit log meta) gets `team_id NOT NULL` from day one. SSH keys hang off `user_id` (a user's keys are theirs, scoped by personal team membership, not the team itself — exception noted). Add a `tests/test_schema_invariants.py` that introspects metadata and asserts every table outside an explicit allowlist has `team_id` or a documented justification.

### Pitfall A6: Master key permissions or ownership wrong

**What goes wrong:** Installer creates `/etc/proxmox-gui/master.key` as root:root mode 0644. Anyone on the LXC reads cluster tokens. (Or: app runs as `proxmox-gui` user but can't read because file is `root:root 0600`.)
**How to avoid:** Installer must:
1. Create the service user (`useradd -r -s /usr/sbin/nologin proxmox-gui`)
2. `mkdir -p /etc/proxmox-gui && chown proxmox-gui:proxmox-gui /etc/proxmox-gui && chmod 0700 /etc/proxmox-gui`
3. `dd if=/dev/urandom of=/etc/proxmox-gui/master.key bs=32 count=1`
4. `chown proxmox-gui:proxmox-gui /etc/proxmox-gui/master.key && chmod 0400 /etc/proxmox-gui/master.key`
5. systemd unit `User=proxmox-gui` so the app reads as that user.

App's startup check: `os.stat(path).st_mode & 0o077 == 0` (no group/other access). Refuse to start otherwise.

### Pitfall A7: SvelteKit fetch from `+layout.server.ts` doesn't carry cookies on first load

**What goes wrong:** Server-side fetch from SvelteKit to FastAPI doesn't include the browser's cookies unless we use the special `fetch` injected into the load function.
**How to avoid:** Use `event.fetch` (provided by SvelteKit) for server-side calls, not the global `fetch`. [CITED: svelte.dev/docs/kit/hooks#Server-hooks-handleFetch] In our same-origin setup this just works out of the box.

### Pitfall A8: PAT prefix collision with bearer JWT

**What goes wrong:** A bearer header that's actually a stale access JWT (because the front-end retried with `Authorization: Bearer ...` instead of relying on the cookie) gets mis-routed through the PAT branch and fails.
**How to avoid:** Branch only on `token.startswith("pat_")`. Anything else under `Authorization: Bearer` is rejected as "unsupported auth scheme" — we explicitly do not accept bearer JWTs. The UI uses cookies exclusively (D-09); only programmatic clients use PATs.

### Pitfall A9: First-run wizard cannot reach the API because origin mismatch

**What goes wrong:** Operator hits `http://lxc-ip:443` (raw IP, not the configured hostname), gets a cert error, and the SvelteKit `/api/v1/setup/status` call resolves through a different host header than Caddy expects — endpoint not found.
**How to avoid:** Caddy's hostname directive accepts the configured hostname or fall through to `:443 { ... }` which matches any host. For first-run, use the no-hostname form (or `0.0.0.0:443`) with `tls internal` so the bootstrap works on a fresh LXC with no DNS. The wizard's last step ("Done") prompts the operator to configure a real hostname and reload Caddy.

### Pitfall A10: Pitfall 9 (ticket 2h expiry) leaking into our session model

**What goes wrong:** Developer reads "Proxmox tickets expire in 2h" and starts thinking our session JWT should match. Our session lifetime is unrelated to PVE.
**How to avoid:** Document explicitly in `app/core/jwt.py`: "TTLs from D-10 (15min access / 7d refresh) are app-internal and have nothing to do with PVE ticket lifetime. We never use PVE tickets for backend auth — only tokens (D-03)."

```python
@router.post("/login", response_model=LoginResponse)
async def login(
    payload: LoginRequest,
    response: Response,
    request: Request,
    db: AsyncSession = Depends(get_db),
):
    # constant-time lookup
    user = (await db.execute(
        select(User).where(User.username == payload.username)
    )).scalar_one_or_none()

    # always verify against *some* hash, even for missing users, to avoid user enumeration
    dummy_hash = "$argon2id$v=19$m=65536,t=3,p=4$..."  # precomputed
    if user is None:
        verify_password(payload.password, dummy_hash)
        raise HTTPException(401, "Invalid credentials")

    if not verify_password(payload.password, user.password_hash):
        raise HTTPException(401, "Invalid credentials")

    if not user.is_active:
        raise HTTPException(403, "Account disabled")

    # mint tokens
    access = issue_access_token(user.id, is_admin=user.is_admin)
    refresh_secret, refresh_row = await issue_refresh_token(
        db, user_id=user.id,
        user_agent=request.headers.get("User-Agent", ""),
        ip_address=request.client.host if request.client else "",
    )
    csrf_secret = secrets.token_urlsafe(32)

    # set cookies (D-09)
    cookie_kwargs = dict(httponly=True, secure=True, samesite="lax", path="/")
    response.set_cookie("access_token", access, max_age=15*60, **cookie_kwargs)
    response.set_cookie("refresh_token", refresh_secret, max_age=7*24*3600, **cookie_kwargs)
    # CSRF cookie is JS-readable (D-13)
    response.set_cookie("csrf_token", csrf_secret, max_age=7*24*3600, secure=True, samesite="lax", path="/")

    return LoginResponse(user_id=user.id, username=user.username, is_admin=user.is_admin)
```

### SSH key parse with fingerprint

```python
# app/ssh_keys/service.py
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives import hashes
import base64

def parse_ssh_pubkey(text: str) -> tuple[str, str]:
    """Returns (normalized_openssh, sha256_fingerprint).
    Raises ValueError on bad input."""
    text = text.strip()
    try:
        key = serialization.load_ssh_public_key(text.encode("utf-8"))
    except (ValueError, Exception) as e:
        raise ValueError(f"Invalid SSH public key: {e}")
    der = key.public_bytes(
        encoding=serialization.Encoding.OpenSSH,
        format=serialization.PublicFormat.OpenSSH,
    )
    digest = hashes.Hash(hashes.SHA256())
    # fingerprint is over the binary "wire" format, not OpenSSH text
    # Parse the wire format: <type-string-len><type-string><key-data>
    # Easier: use the OpenSSH base64-decoded blob
    parts = text.split()
    if len(parts) < 2:
        raise ValueError("Malformed SSH public key (expected '<type> <base64> [comment]')")
    blob = base64.b64decode(parts[1])
    digest.update(blob)
    fp = base64.b64encode(digest.finalize()).decode("ascii").rstrip("=")
    return der.decode("utf-8").strip(), f"SHA256:{fp}"
```

```bash
# deploy/install.sh — one-line bootstrap (DEPLOY-01)

# 3. Configuration prompts (or env vars)

    --hostname "$HOSTNAME" \
    --cores "$CPU" --memory "$RAM_MB" \
    --rootfs "$STORAGE:$DISK_GB" \
    --net0 "name=eth0,bridge=$BRIDGE,ip=dhcp" \
    --unprivileged 1 \
    --features "nesting=1,keyctl=1" \
    --onboot 1

pct start "$CTID"
sleep 5  # wait for net

# 6. Run inner bootstrap inside the LXC
pct exec "$CTID" -- bash -c "
    set -euo pipefail
    apt-get update
    apt-get install -y curl ca-certificates
    curl -fsSL '$REPO_URL/raw/$RELEASE/deploy/lxc/bootstrap.sh' | bash
"

# 7. Print URL + bootstrap hint

echo
```

## State of the Art

| Old Approach | Current Approach (2026-05) | When Changed | Impact |
|---|---|---|---|
| passlib | pwdlib[argon2] | passlib EOL 2020, broken on Py3.13+ | Must use pwdlib for new projects |
| python-jose | PyJWT | jose unmaintained since 2023 | Use PyJWT for any new JWT work |
| SQLAlchemy 1.x classical | SQLAlchemy 2.0 async + Mapped[] | 2.0 release 2023-01 | Modern type-safe pattern; aiosqlite required |
| Pydantic v1 | Pydantic v2 | v2 GA 2023-06 | FastAPI 0.100+ requires v2; rewrite-level breaking |
| Tailwind v3 | Tailwind v4 | 2025; @import-CSS-based config | No PostCSS config; CSS-first |
| Svelte 4 / `$:` reactivity | Svelte 5 + runes (`$state`, `$derived`, `$effect`) | Svelte 5 GA 2024-10 | Legacy still works; new projects use runes |
| Cookies + `SameSite=Strict` | `SameSite=Lax` (with CSRF token for state-changing reqs) | CSRF protection refined 2023+ | Strict breaks many redirect-from-IdP flows; Lax + token is current best-practice |
| Server-side sessions | Stateless JWT (access) + DB refresh w/ rotation | Auth0 pattern, 2020+ | Revocable + scalable; rotation detects replay |
| FastAPI on_event hooks | `lifespan` context manager | FastAPI 0.93+ | on_event deprecated; lifespan handles startup/shutdown |
| Alembic without batch mode for SQLite | `render_as_batch=True` | Standard for ~10 years now | Mandatory; not optional |

**Deprecated / out:**
- `passlib`, `python-jose`, `bcrypt` direct usage (use pwdlib), `Celery` for async (use arq), Pydantic v1.
- SvelteKit `adapter-auto` for self-hosted (use `adapter-node` explicitly).
- Server-rendered Flask + Jinja for admin tools (SvelteKit + Tailwind is now the cheaper option per LOC).

## Open Questions

1. **Backports vs pyenv for Python 3.12 on Debian 12**
   - What we know: Debian 12 default is 3.11; backports may have 3.12, but I haven't probed `apt-cache policy python3.12` on a real Debian 12 LXC.
   - What's unclear: stability of backports python3.12 vs maintenance burden of pyenv.
   - Recommendation: planner spawns a 10-min task "probe Debian 12 backports for python3.12; if absent, use deadsnakes equivalent or pyenv." Pick one in the install script. Phase 5 (self-update) revisits.

2. **Bootstrap token in installer**
   - What we know: D-18 says "lenient validation" — only admin is mandatory. D-19 says stepper UX.
   - What's unclear: whether the first-run flow should require a one-shot bootstrap token (printed by installer, consumed once) or rely purely on the "no admin yet" predicate.
   - Recommendation: ship without bootstrap token in v1 to keep the wizard frictionless. Add a Phase 5 hardening option to require it. Document in CONTEXT addendum.

3. **Login rate limiting in Phase 1 vs Phase 5**
   - What we know: CONTEXT marks "in-memory bucket for v1" as Claude's discretion.
   - What's unclear: required to ship Phase 1, or carry to a polish phase?
   - Recommendation: simple in-memory per-IP+username bucket from the start (5 attempts / 15min, exponential backoff). ~30 lines of code; saves a v1 security debt item.

4. **CSRF token rotation**
   - What we know: D-13 says double-submit cookie.
   - What's unclear: does the CSRF cookie rotate on each refresh, or stay stable per session?
   - Recommendation: rotate on every refresh (tied to refresh-token rotation chain). Trivial to implement; future-proofs against token-pinning attacks.

5. **OpenAPI tag / operationId conventions**
   - What we know: API-03 requires auto-generated OpenAPI; UI consumes via openapi-ts.
   - What's unclear: explicit naming convention.
   - Recommendation: per-router tag (`auth`, `users`, `teams`, `clusters`, `setup`, `me`); explicit `operation_id="login"` etc. on every route so the generated TS client has stable method names. **Locks the contract** — renames are breaking changes.

## Security Domain

This phase establishes the auth surface. Security review applies.

### Applicable ASVS (4.0.3) Categories

| ASVS Category | Applies | Standard Control |
|---|---|---|
| V2 Authentication | yes | pwdlib[argon2] Argon2id; constant-time verify; dummy hash on missing user (avoid enumeration) |
| V3 Session Management | yes | Stateless JWT access (15min) + DB-stored opaque refresh (7d) with rotation + replay detection |
| V4 Access Control | yes | `get_current_principal` + `require_admin` dependencies; team-membership checks at service layer (D-07: equal editors) |
| V5 Input Validation | yes | Pydantic v2 on every route schema; SSH key parse via `cryptography` library; username/email regex; password length policy |
| V6 Cryptography | yes | Fernet (AES-128-CBC + HMAC-SHA256) — `cryptography.fernet`. Never hand-roll. JWT HS256 with key from `/etc/proxmox-gui/jwt.secret` |
| V7 Error Handling | yes | Generic 401/403/404 for unauth/forbidden/missing; never echo back which-of-multiple-credentials failed |
| V8 Data Protection | yes | PVE tokens + refresh tokens Fernet-encrypted in DB; master.key on disk 0400 owned by service user |
| V9 Communication | yes | Caddy auto-HTTPS or `tls internal`; FastAPI binds 127.0.0.1 only (Caddy is the only TLS terminator) |
| V12 Files & Resources | partial | SSH key upload max size (e.g., 4 KB); strict UTF-8 decode |
| V14 Configuration | yes | Master key file permission check at boot; refuse to start if mode not 0400 + correct owner |

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---|---|---|
| SQL injection | Tampering | SQLAlchemy ORM with parameterized queries; never string-format SQL |
| User enumeration via login error timing | Information Disclosure | Constant-time verify against a precomputed dummy hash on missing user (Code Example above) |
| Refresh token replay | Spoofing | Single-use refresh + `replaced_by_id` chain detection; reuse of an already-rotated token revokes the entire chain |
| CSRF on state-changing cookie-auth requests | Tampering | Double-submit cookie (D-13); `csrf_protect` dependency on all non-GET routes that allow cookie auth |
| XSS leaking access JWT | Information Disclosure | httpOnly cookie (D-09); JS cannot read access token; CSP via Caddy headers (`default-src 'self'`) |
| Brute-force login | DoS / Elevation | Per-IP+username bucket; exponential backoff; admin alert on >N failures per hour |
| Master.key exfiltration | Information Disclosure (Elevation) | File mode 0400, owned by `proxmox-gui`; systemd `ProtectSystem=full`; included in self-backup encrypted form (Pitfall 22) |
| PAT token leak in logs | Information Disclosure | structlog processor that redacts any field matching `pat_*` or `Authorization` header |
| Tenant scope bypass via team_id forgery | Elevation | Server resolves team from session + URL; never trusts client-supplied team_id |
| PVE token leak via API response | Information Disclosure | Response schemas (pydantic) never include `api_token_secret` or `token_secret`; explicit allowlist |
| Algorithm confusion on JWT | Spoofing | `jwt.decode(..., algorithms=["HS256"])` enforced; never accept `alg=none` |
| Cleartext logs of password | Information Disclosure | structlog processor scrubs `password`, `current_password`, `new_password` fields |
