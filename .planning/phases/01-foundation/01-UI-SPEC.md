# Phase 1 — UI Design Contract

> Visual and interaction contract for Foundation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note:** This project uses SvelteKit, not React/Next.js/Vite. The component layer is `shadcn-svelte` (the SvelteKit port of shadcn/ui). The CLI is `shadcn-svelte@latest` and components live at `src/lib/components/ui/`. The "preset" concept from `ui.shadcn.com/create` does not apply — shadcn-svelte uses the `init` wizard with base-color + CSS path + alias. We pin those choices in this contract.

## Spacing Scale

Declared values (multiples of 4 — Tailwind v4 default `--spacing: 0.25rem`; we exclusively use these tokens):

| Token | Value | CSS | Usage |
|-------|-------|-----|-------|
| xs | 4px | `p-1`, `gap-1` | Icon-to-label gap, badge inner padding |
| sm | 8px | `p-2`, `gap-2` | Compact element spacing inside dense rows (table cell padding) |
| md | 16px | `p-4`, `gap-4` | Default element spacing — form field gap, card inner padding (top/bottom), button vertical padding |
| lg | 24px | `p-6`, `gap-6` | Card inner padding (left/right), section header bottom margin, page header bottom margin |
| xl | 32px | `p-8`, `gap-8` | Outer page padding above 768px, gap between top-level sections |
| 2xl | 48px | `p-12`, `gap-12` | First-run wizard step inner vertical padding |
| 3xl | 64px | `p-16` | Reserved — not used in Phase 1 (allowed for empty-state hero in Phase 4+) |

**Reserved scale for layout chrome (not spacing tokens — fixed pixel dimensions):**

| Element | Value | Notes |
|---------|-------|-------|
| Topbar height | 56px | `h-14`; fixed across all auth'd routes |
| Sidebar width (expanded) | 240px | `w-60`; collapses to 56px (`w-14`) icon-only at <1024px viewport |
| Sidebar collapsed width | 56px | `w-14` |
| Sidebar / content gutter | 0px | sidebar is flush; content area applies its own `lg` left padding |
| Page max content width | 1280px | `max-w-screen-xl`; centered in the content outlet |

## Typography

Font stack (single declaration in `app.css`):

```css
:root {
  --font-sans: 'Inter Variable', ui-sans-serif, system-ui, -apple-system,
               'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
  --font-mono: ui-monospace, 'JetBrains Mono', 'Fira Code',
               'SFMono-Regular', Menlo, Consolas, monospace;
}
```

Inter Variable is self-hosted (no external CDN — single-LXC deployment must work air-gapped).

Type ramp (exactly 4 sizes, exactly 2 weights):

| Role | Size | Weight | Line Height | Letter Spacing | CSS class |
|------|------|--------|-------------|----------------|-----------|
| Body | 14px (0.875rem) | 400 (regular) | 1.5 (21px) | 0 | `text-sm font-normal leading-normal` |
| Label / UI | 13px (0.8125rem) | 500 (medium) | 1.4 (18.2px) | 0.005em | `text-[13px] font-medium tracking-tight` |
| Heading | 18px (1.125rem) | 600 (semibold) | 1.3 (23.4px) | -0.01em | `text-lg font-semibold tracking-tight` |
| Display | 28px (1.75rem) | 600 (semibold) | 1.2 (33.6px) | -0.02em | `text-[28px] font-semibold tracking-tight` |

**Weight rule:** only 400 (regular) and 600 (semibold) ship in Phase 1. The 500-medium row is permitted because it is Inter's optical-axis "ui label" weight and reads as a single visual step from body — but it is used **only** for labels and tabular column headers, never for content.

**Mono use:** API tokens, PAT secrets, cluster fingerprints, code blocks. Always 13px / 1.5 line-height inside a `<pre>` or inline `<code>`.

**Numeric tabular features:** apply `font-variant-numeric: tabular-nums` to all table-cell numbers (currently none in Phase 1, but the rule lives here for future phases).

### Accent reserved for (explicit allow-list)

The blue primary accent appears **ONLY** on:

1. The single Primary CTA per page/dialog (`<Button variant="default">`)
2. Text links inside body copy (`<a class="text-primary underline-offset-4 hover:underline">`)
3. The active sidebar-nav item's left-edge indicator (3px bar) and icon
4. Form-field focus rings (2px offset)
5. The current step indicator in the first-run wizard stepper
6. The "Primary" badge variant (used for the user's own role label in the user list)

The accent is **NEVER** used for:
- Generic borders
- Hover backgrounds on non-active list items
- Secondary buttons (those are `variant="outline"` or `variant="ghost"`)
- Decorative icons
- Card backgrounds
- Default text

## Component States (mandatory)

Every interactive component must implement these states explicitly. The checker validates presence.

| Component | States |
|-----------|--------|
| Button | default, hover, focus-visible (2px ring), active (translate-y-px or bg-shift), disabled (opacity-50, no pointer), loading (spinner replaces icon + label muted) |
| Input | default, hover (border lift to `--border` darker), focus-visible (2px primary ring), invalid (`border-destructive` + `text-destructive` helper), disabled (opacity-60) |
| Form field | label (always above), input, helper text (always reserved 18px below — prevents layout shift), error text replaces helper text |
| Data table row | default, hover (`bg-muted`), selected (`bg-primary/5` + `border-l-primary`), empty (table-level empty state, see below) |
| Dialog | open animates in 150ms, focus traps to first focusable, ESC closes, click-outside closes EXCEPT destructive-confirm dialogs (which require explicit cancel) |
| Toast (sonner) | success (green icon), error (red icon), info (blue icon), warning (amber icon); positioned bottom-right; auto-dismiss 5s except error which is sticky until dismissed |

### Required loading / empty / error states per surface

| Surface | Loading | Empty | Error |
|---------|---------|-------|-------|

### Destructive confirmations (locked pattern)

**Locked pattern:** type the **target's name** to confirm — NOT the literal word "DELETE". This is more user-meaningful and matches Hetzner / Linode / GitHub patterns.

For each destructive action below, the confirmation dialog has:
1. Heading: action-specific (see table)
2. Body: explains consequences in one sentence
3. Input: "Type **{target_name}** to confirm" — input must equal target name exactly (case-sensitive) before the destructive button enables
4. Footer: "Cancel" (ghost, left) and primary destructive button (red, right) — disabled until input matches

| Action | Heading | Body | Confirm button label |
|--------|---------|------|----------------------|
| Disable user | "Disable {username}?" | "{username} won't be able to sign in. Active sessions are revoked immediately. You can re-enable them later." | "Disable user" |
| Delete user | "Delete {username}?" | "Their account is removed permanently. Their team memberships are dropped. VMs they created stay with the team. This can't be undone." | "Delete user" |
| Delete cluster | "Delete {cluster_name}?" | "This GUI will stop managing this cluster. The Proxmox cluster itself is not affected. Encrypted tokens stored here are destroyed." | "Delete cluster" |
| Delete SSH key | "Delete '{key_label}'?" | "This key is removed from your account. Existing VMs that already have this key keep it." | "Delete key" |
| Revoke PAT | "Revoke '{token_name}'?" | "Any application using this token loses access immediately. This can't be undone." | "Revoke token" |

For the **typed-name** confirmation:
- Comparison is exact, case-sensitive, trimmed of leading/trailing whitespace only
- Show a subtle inline hint when input is non-empty and doesn't match: "Doesn't match — type the name exactly."
- ENTER inside the input does NOT submit (must click the destructive button)

## Form Patterns

All forms use **shadcn-svelte `form` block (Formsnap)** with zod schemas. Validation rules below are the contract; executor authors the zod schema.

### Field layout

```
Label (13px / 500 / foreground)              ← always above input
[ Input field ]                              ← 36px tall (h-9)
Helper or error text (13px / 400 / muted)    ← reserved row, no layout shift
                                                error replaces helper (red)
```

Field-to-field vertical gap: `md` (16px).

### Inline + summary validation

On submit failure:
1. Each invalid field shows its inline error (red border + red helper text replacement)
2. **A summary alert appears at the top of the form** listing all errors as a bulleted list, with each item being a link that focuses the offending field on click
3. The summary alert uses `Alert variant="destructive"` with `AlertTriangle` icon, heading "Please fix the following:"

### Required password rules (Phase 1)

- Minimum length: 12 characters
- No other complexity rules (zxcvbn-style strength meter is Claude's discretion per CONTEXT.md — defer to executor; the contract only locks the minimum)
- Password input always has visibility toggle (Eye / EyeOff)

### Required SSH key validation

- Parse with `cryptography.hazmat.primitives.serialization.load_ssh_public_key` on the backend
- UI shows derived fingerprint (SHA256, base64) once accepted — read-only field below the textarea
- Label field required (so the user can identify multiple keys)

### Required cluster registration form

Fields (in order):
1. Name — short identifier, slug-like
2. URL — full base URL with scheme (e.g. `https://pve.example.com:8006`)
3. API token ID — `user@realm!tokenid` format; help text shows the expected pattern
4. API token secret — `type="password"` with visibility toggle (write-only on edit — field shows placeholder dots and an "Update token" link that reveals the input when clicked)
5. TLS fingerprint — optional; help text "Required only for self-signed certificates."
6. "Test connection" button — secondary action that pings `/version` before save, surfaces success/failure inline; primary "Register cluster" disabled until tested OR explicitly bypassed via "Register without testing" link

The **token field on edit** is the critical security invariant: it MUST NOT pre-fill the existing value. It MUST show a placeholder ("●●●●●●●●") and require explicit click to change.

## Theme Toggle Contract

`ThemeToggle` is a `DropdownMenu` triggered by an icon button in the topbar. Tri-state:

| State | Icon | Behavior |
|-------|------|----------|
| Light | `Sun` | Force light: `<html>` has no `dark` class; `localStorage.theme = "light"` |
| Dark | `Moon` | Force dark: `<html class="dark">`; `localStorage.theme = "dark"` |
| System | `Monitor` | Follow `prefers-color-scheme`; `localStorage.theme = "system"` (or absent) |

**Default for new visitors:** system. **FOUC mitigation:** an inline `<script>` in `app.html` before any CSS reads `localStorage.theme` (or `matchMedia`) and applies `class="dark"` to `<html>` synchronously — this is the only inline-script exception we allow.

```html
<!-- src/app.html (inline before <link rel="stylesheet">) -->
<script>
  (function () {
    var t = localStorage.getItem('theme');
    var d = t === 'dark' || ((!t || t === 'system') && window.matchMedia('(prefers-color-scheme: dark)').matches);
    if (d) document.documentElement.classList.add('dark');
  })();
</script>
```

## Accessibility Floor (Phase 1)

The Phase 5 a11y audit will be exhaustive; Phase 1 must meet this minimum so the audit doesn't require rework:

- All interactive elements reachable by keyboard, visible focus ring (`--ring`, 2px offset)
- All icon-only buttons have `aria-label`
- All form inputs have an associated `<label>` (Formsnap handles this)
- All dialogs have `role="dialog"` + `aria-labelledby` (bits-ui handles)
- All error messages have `aria-live="polite"`
- Contrast ratio AA minimum for body text on background in BOTH light and dark modes — token values above already pass; checker should re-validate after any token change
- No information conveyed by color alone (status pills always have an icon + text)
- Skip-to-content link in the app shell
