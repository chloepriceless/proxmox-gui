<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → cloud-init form fields | User-supplied ciuser/cipassword/sshkeys/ipconfig — a guest-credential-injection vector |
| browser → ISO URL-download | User-supplied download URL — an SSRF vector (the backend, Plan 04-05, is the enforcement point) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-12-01 | Elevation | Cloud-init pre-seeding root access with bad input | mitigate | The editor is form-driven (D-09) — a restricted field set, no raw YAML; the backend `validate_cloudinit_form` (Plan 04-05) hard-rejects malformed SSH keys / invalid `ciuser` and requires `cipassword`; the editor disables the wizard CTA on any `hard_errors` so a malformed config cannot be submitted |
| T-04-12-02 | Information disclosure | `cipassword` leaked into the wizard draft / logs | mitigate | `cipassword` is entered via `PasswordInput` (masked) and is NOT persisted to the `wizardDraft` `sessionStorage` store (Plan 04-09 T-04-09-02) — it lives only in the in-memory form state and the create payload over HTTPS |
| T-04-12-03 | Tampering | Cross-site scripting via cloud-init YAML preview | mitigate | The YAML pane renders `YamlLine.text` as Svelte text bindings (auto-escaped) — never `{@html}`; the lines come from the backend `render_cloudinit_preview`, not raw user markup |
| T-04-12-04 | Information disclosure | ISO URL-download SSRF | mitigate | The frontend only submits the URL; the backend `enqueue_iso_download` (Plan 04-05) rejects non-http(s) schemes and PVE's `download-url` runs the fetch on the PVE node — the GUI never resolves or proxies the URL; the frontend gate is not the boundary |
| T-04-12-05 | Spoofing | Cross-tenant SSH key exposure in the multi-select | mitigate | The SSH-key multi-select pre-fills from the team members' key sets via the team-scoped Phase-1 ssh-keys API — it cannot enumerate keys outside the user's team |
</threat_model>
