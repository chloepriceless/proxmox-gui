<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → VM create API | User-controlled source kind, source VMID, sizing, node, storage, network |
| browser → networks read API | The network picker reads only the team-scoped, admin-granted network set |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-12-01 | Elevation | Cloning a source VM the user does not own | mitigate | The template-clone / VM-clone source `Select`s are populated only from the user's team-scoped inventory; the backend `createQemu` (Plan 04-04) re-resolves source ownership via `require_resource_access` — a forged `source_vmid` → 403 |
| T-04-12-02 | Tampering | Client bypassing node-fit / quota gating | mitigate | `NodeSelect` and `QuotaDeltaLine` are UX guidance; the backend runs the row-locked quota admission before reserving the VMID (Plan 04-04) — a forged over-quota request → 409; node-fit is advisory and PVE rejects an impossible placement |
| T-04-12-03 | Information disclosure | Cross-tenant SDN visibility in the picker | mitigate | `NetworkPicker` renders only what `GET /clusters/{id}/networks` returns — the backend (Plan 04-07) already filters SDN VNets to the team's admin-granted scope (D-19); the picker never enumerates un-granted networks |
| T-04-12-04 | Spoofing | A non-applied VNet selected for a real create | mitigate | The picker renders a non-`applied` VNet as non-pickable (the `applied` flag from Plan 04-07's `APPLIED STATE READ:` mechanism) — only an applied, usable VNet can be chosen |
</threat_model>
