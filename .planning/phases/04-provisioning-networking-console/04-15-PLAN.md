<!-- The mint route contract (Plan 04-08) — the executor uses this directly. -->

`api.console.mintVncProxy({ clusterId, vmid, kind })` → `VncProxyResponse`:
```typescript
interface VncProxyResponse {
  ticket: string;     // raw PVE vncticket — NOT used by the frontend
  port: number;       // 5900-5999 — NOT used by the frontend
  relay_url: string;  // GUI-origin path: /api/v1/ws/console/{cluster_id}/{vms|lxcs}/{vmid}
}
```
The frontend uses ONLY `relay_url`. It is a relative GUI-origin path; the relay backend
holds the Proxmox `:8006` leg and the ticket — neither ever reaches the browser.

The relay WebSocket endpoint (Plan 04-08, `console/proxy.py`) is mounted at:
`/api/v1/ws/console/clusters/{cluster_id}/{kind}/{vmid}` — a bidirectional binary relay
of the noVNC RFB protocol. The relay mints its own fresh ticket per connection.

`console-tab.ts` currently exports: `ConsoleState`, `iframeVisible()`, `isSafeRelayUrl()`,
`placeholderBody()`, `consoleIframeSrc()`.
</interfaces>

<spike_contract>
<!-- 04-SPIKE-novnc.md §7 "iframe src URL shape" — the AUTHORITATIVE contract. -->

The Console tab's `<iframe>` `src` points at the GUI's own origin — never at Proxmox:

    <iframe title="Console for {name}"
            src="/console/embed?ws=/api/v1/ws/console/clusters/{id}/{kind}/{vmid}">

The iframe loads a GUI-served noVNC client page configured to open the GUI relay WS path,
NOT `wss://pve-host:8006`. UI-SPEC §704 forbids `@novnc/novnc` as a bundled npm
dependency. The load-bearing invariant: the iframe's WebSocket target is a GUI-origin
path; the Proxmox vncticket + `:8006` host never reach the browser. The iframe is
rendered only after the "Open console" click (CON-02) and carries a `title` attribute.
</spike_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /console/embed `ws` query param | The embed page receives an attacker-influenceable `ws` query string and uses it to open a WebSocket |
| /console/embed iframe → GUI relay WS | The vendored RFB client opens a WebSocket to a GUI-origin path |
| vendored noVNC source → build | Third-party MPL-2.0 source is added to the repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-15-01 | Tampering | `/console/embed` `ws` query param | mitigate | `+page.ts` load validates `ws` is a same-origin relative path starting `/api/v1/ws/console/`, rejects absolute URLs (`^[a-z]+:` / `^//`) and any `:8006` — an attacker-crafted `ws` pointing the RFB client at an attacker host or directly at Proxmox is refused; the page renders an error state instead |
| T-04-15-02 | Information disclosure | iframe src in `ConsoleTab` | mitigate | `consoleIframeSrc` only accepts a `/console/embed?ws=` GUI-origin URL and rejects any `:8006` / `vncwebsocket` URL; `consoleEmbedSrc` runs the relay path through `isSafeRelayUrl` before composing — the Proxmox host + vncticket never reach the browser (CON-03 preserved) |
| T-04-15-03 | Elevation of privilege | iframe sandboxing | mitigate | The `<iframe>` carries `sandbox="allow-scripts allow-same-origin"` — the minimum the RFB client needs; `allow-top-navigation` / `allow-popups` / form submission are not granted (WR-02 — the verifier flagged the missing sandbox attribute) |
| T-04-15-04 | Spoofing | console relay WS handshake | accept | Auth-before-`accept()` (cookie-only, `close(1008)`) is enforced server-side by the Plan 04-08 relay endpoint — VERIFIED in 04-VERIFICATION.md; this plan changes only the frontend iframe wiring and does not touch that handshake |
| T-04-15-05 | Tampering | vendored noVNC source supply chain | accept | noVNC is pinned to a specific release (`v1.6.0`) with provenance recorded in `vendor/novnc/README.md`; the vendored tree is in-repo and reviewable in the commit diff — no runtime fetch, no floating npm range |
