<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → console iframe / relay | The iframe points only at the GUI's own reverse-proxied URL — never the Proxmox host |
| browser → notifications feed | The feed is scoped to the caller's own teams' jobs |
| admin → Networks tab | Only an admin scopes a team's network visibility |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-14-01 | Information disclosure | Proxmox-host / vncticket exposure via the Console tab | mitigate | `ConsoleTab` points the iframe `src` only at the `relay_url` returned by `mintVncProxy` — the GUI's own reverse-proxied URL (CON-03); the Proxmox host `:8006` and the vncticket never reach the browser; a test asserts the src has no `:8006` |
| T-04-14-02 | Spoofing | Console minted on page load / without a click | mitigate | `ConsoleTab` renders NO iframe and makes NO mint call until the user clicks "Open console" (CON-02); the backend mint route (Plan 04-08) re-checks resource ownership before minting |
| T-04-14-03 | Information disclosure | Cross-tenant notification leakage | mitigate | `list_notifications` scopes the feed to the caller's own team ids (`_team_ids_for_user`) — a user never sees another tenant's job completions |
| T-04-14-04 | Elevation | Network-scoping CRUD via the Networks tab by a non-admin | mitigate | `NetworksTab` is rendered inside the already-admin-gated `/admin/teams/{id}` page; the real enforcement is the `require_admin` on the backend `PUT /admin/teams/.../networks` (Plan 04-07) — the frontend gate is defense-in-depth |
| T-04-14-05 | Tampering | Stale notification last-seen replayed to hide an alert | accept | The `last_seen_at` cursor only affects the unread COUNT, not the feed contents — a tampered cursor at most under/over-counts unread items the user can still see in the panel; no security decision rides on it |
</threat_model>
