**`backend/app/provisioning/cloudinit.py`** — a pure stateless transform module (no DB, no PVE — modelled on `audit/csv.py`):

- A `YamlLine` dataclass: `text: str`, `injected: bool`. A `CloudInitForm` shape (or reuse the Cloud-Init fields from `CreateQemuRequest`): `ciuser`, `cipassword`, `sshkeys: list[str]`, `ip_mode` (`auto`/`dhcp`/`static`), `ip_address`, `gateway`, `nameservers: list[str]`, optional `packages: list[str]`, optional `runcmd: list[str]`.

- `render_cloudinit_preview(form) -> list[YamlLine]` — renders the effective `#cloud-config` user-data. The user-set fields (`ciuser`→`users[].name`, `sshkeys`→`ssh_authorized_keys`, `ipconfig0`-derived NIC config) are `injected=False`. The PVE-injected lines the user did NOT set — `chpasswd: {expire: false}`, the auto-generated `meta-data`, the default package handling — are `injected=True` (D-10 — the frontend dims them and badges "PVE default", satisfying VM-06). The first line is `#cloud-config` (`injected=False`).

- `validate_cloudinit_form(form) -> CloudInitVerdict` — a hand-rolled field validator (RESEARCH A5 + the Standard Stack recommendation — no `cloud-init` CLI dependency). Returns a `CloudInitVerdict` with `hard_errors: list[FieldError]` + `soft_warnings: list[str]` — RETURNS the verdict, never raises (mirrors the Phase-2 quota-admission verdict shape). Rules:
  - **Hard errors (block submit — D-12):** missing required `cipassword` (D-11 — `cipassword` is required); `ciuser` with characters outside a valid Linux username set; an unparseable / malformed SSH public key (reuse the Phase-1 `ssh_keys` parse/validate helper if importable); a `static` IP mode with a missing or malformed `ip_address`/`gateway`; a `cloud-image`/`template-clone`/`blank-iso` config that resolves to no `ipconfig0` at all (Pitfall 6 — a cloud-init NIC with no `ipconfig0` boots with no network).
  - **Soft warnings (non-blocking — D-12, Pitfall 14):** DNS / `nameservers` set while `ip_mode` is `dhcp` (DHCP supplies DNS; the guest may ignore the cloud-init DNS); any other best-effort advisory. NO per-distro compatibility matrix (D-14 — declined for v1).
  - Each `FieldError` carries the offending field name so the frontend can attach the inline message (UI-SPEC §Cloud-Init editor — the offending field gets the inline error).

This module is the backend half of the two-pane editor — the frontend (Plan 04-13) calls a route that wraps `render_cloudinit_preview` for the live YAML pane and `validate_cloudinit_form` for the block-hard/warn-soft verdict. Expose a small route in `provisioning/routes.py` (extend the file Plan 04-04 created): `POST /clusters/{id}/provisioning/cloudinit/preview` returning `{lines: [...], verdict: {hard_errors, soft_warnings}}` so the editor gets both in one call.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/PAT client → ISO download API | User-supplied download URL — an SSRF vector |
| browser → cloud-init form fields | User-supplied ciuser/cipassword/sshkeys/ipconfig — a guest-credential injection vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | Information disclosure | ISO URL-download SSRF | mitigate | `enqueue_iso_download` rejects any non-http(s) URL scheme (422); PVE's `download-url` endpoint runs the fetch on the PVE node, not the GUI process — the GUI never resolves or proxies the URL itself (Pitfall 7, V12) |
| T-04-05-02 | Elevation | Cloud-init pre-seeding root access | mitigate | The form-driven editor (D-09) restricts the field surface to a known set; `validate_cloudinit_form` hard-rejects malformed SSH keys and invalid `ciuser`; `cipassword` is required (D-11) — no anonymous-access config; VMs land in the team pool (enforced by Plan 04-04's `pool=`) |
| T-04-05-03 | Elevation | ISO download admin-gating bypass concern | accept | D-17 deliberately opens ISO URL-download to any authenticated user; the threat is bounded — the download runs on the PVE node as the team token, lands on team-scoped storage, and is audited; documented as an authenticated-user capability |
| T-04-05-04 | Tampering | Malformed cloud-init breaks the guest silently | mitigate | The block-hard validator rejects a missing `ipconfig0` (Pitfall 6) before submit; soft warnings surface DHCP-DNS mismatch (Pitfall 14) — the user is informed, not silently bricked |
</threat_model>
