<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → LXC create / community-script API | User-controlled sizing, template, script slug, script options, network |
| upstream community-scripts repo → browser (catalog display) | The catalog the browser renders is the commit-pinned backend snapshot — not a live upstream fetch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-11-01 | Spoofing | A user deploying an unreviewed community-script unknowingly | mitigate | `ScriptDetailPanel` is a MANDATORY pre-deploy disclosure (LXC-04) — the source link, commit hash, and last-reviewed date are shown, plus the `ShieldQuestion` attribution notice, before the user can advance to deploy |
| T-04-11-02 | Elevation | Catalog Sync exposed to a non-admin | mitigate | The Sync-catalog control renders only on the admin page (already admin-gated); the real enforcement is the `require_admin` on the backend `POST /catalog/sync` (Plan 04-06) — the frontend gate is defense-in-depth, not the boundary |
| T-04-11-03 | Tampering | Client-built create payload bypassing quota/tenancy | mitigate | `buildLxcRequest` only assembles the wizard form values; quota admission and tenancy are enforced server-side (Plan 04-04) — a 409/403 surfaces as an inline mapped error; the client cannot bypass admission |
| T-04-11-04 | Information disclosure | Stored XSS via community-script catalog metadata (name/description) | mitigate | Catalog `name`/`description` are rendered as Svelte text bindings (auto-escaped) — never `{@html}`; the catalog data itself is the backend's commit-pinned snapshot, not arbitrary user input |
</threat_model>
