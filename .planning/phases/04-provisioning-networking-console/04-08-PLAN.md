<objective>
Build the embedded-noVNC console backend: the `vncproxy` ticket mint, the reverse-proxied bidirectional WebSocket relay, and any Caddyfile change. This is the spike-gated console domain — the relay design, the single-encoding rule, the self-signed-cert handling, and the Caddyfile delta are all pinned by spike 04-03 (`04-SPIKE-novnc.md`).

Purpose: CON-01 needs an embedded console for any VM/LXC the user owns. CON-02 needs the `vncticket` minted server-side on click (never on page load — ~30-40s lifetime, Pitfall 3). CON-03 needs the GUI to reverse-proxy the WebSocket so the Proxmox host is never directly exposed to the browser. The relay loop, the upstream-WS library choice, the encoding rule, and the Caddy tuning are pinned by spike 04-03.

Output: `POST /api/v1/clusters/{id}/{vms|lxcs}/{vmid}/console/vncproxy` (mint on click), the `/api/v1/ws/console/...` reverse-proxied relay endpoint, and the Caddyfile change (if the spike said one is needed).
</objective>

<!-- The auth-before-accept handshake and the spike contract. -->

The console WebSocket reuses the EXACT auth-before-accept pattern from `backend/app/jobs/ws.py` (`_resolve_ws_user` lines ~46-83): read the `access_token` cookie, `decode_access_token`, load the `User`, and authenticate BEFORE `websocket.accept()`; `close(1008)` on failure; cookie-only — no PAT.

The resource-ownership check reuses the Phase-2/3 `require_resource_access` / `ResolvedResource` pattern from `backend/app/inventory/access.py` — both the mint route AND the relay endpoint resolve ownership before proceeding (cross-tenant → 403 / close).

The spike pins these (read `04-SPIKE-novnc.md`):
- `VNCPROXY MINT:` — the exact `POST /nodes/{node}/{qemu|lxc}/{vmid}/vncproxy` path + the response fields (`ticket`, `port`, ...)
- `ENCODING:` — where in the relay chain the `vncticket` is URL-encoded exactly once
- `RELAY:` — the upstream-WS library (`websockets` / `aiohttp` / `httpx`) and whether a new dependency is required
- `CADDY:` — whether a Caddyfile `handle` block is needed and the exact directives
- `SELF-SIGNED CERT:` — how the GUI→Proxmox `wss://...:8006` leg handles the self-signed cert
- `TICKET LIFETIME:` — confirms mint-on-click only

The `vncproxy` connector method is structurally a normal `_call_with_breaker` POST (04-PATTERNS.md §connector EXTEND): `POST .../vncproxy` returning `{ticket, port}`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser iframe → GUI WS relay | Untrusted browser; the relay authenticates before `accept()` and never exposes the Proxmox host |
| GUI WS relay → Proxmox `wss://...:8006` | The only leg that holds the vncticket; the ticket never reaches the browser as a Proxmox-host URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-08-01 | Information disclosure | vncticket / Proxmox host exposure (SSRF surface) | mitigate | CON-03: the GUI reverse-proxies the WS — the mint route returns only the GUI's own relay URL (no `:8006`, no raw `vncwebsocket` URL); the relay mints its own ticket and holds it only on the upstream leg; the browser never receives a Proxmox-host URL or a ticket |
| T-04-08-02 | Spoofing | Unauthenticated console WS handshake | mitigate | The relay reuses `jobs/ws.py`'s auth-before-accept — the `access_token` cookie is validated BEFORE `accept()`, cookie-only (no PAT), `close(1008)` on failure; no unauthenticated socket is ever accepted |
| T-04-08-03 | Elevation | Cross-tenant console access | mitigate | Both the mint route (`require_resource_access`) AND the relay endpoint resolve resource ownership before proceeding — a console for a resource the user does not own → 403 / WS close (CON-01 is "any VM/LXC the user OWNS") |
| T-04-08-04 | Tampering | Double-encoded / malformed vncticket → silent failure or relay confusion | mitigate | The `vncticket` is URL-encoded EXACTLY ONCE at the single spike-named location (Pitfall 3); no hop re-encodes; a unit test asserts the single-encoding invariant |
| T-04-08-05 | Spoofing | Replayed / stale vncticket | mitigate | The relay mints a fresh ticket per connection on click (CON-02 — never on page load); the ~30-40s lifetime bounds any leaked ticket; the relay connection is bounded by the ticket and closes cleanly on upstream expiry |
| T-04-08-06 | Information disclosure | Upstream TLS — accepting any cert (MITM) | mitigate | The upstream `wss://...:8006` leg reuses the per-cluster `verify_ssl` TLS posture per the spike's `SELF-SIGNED CERT:` verdict — the relay does not silently disable verification beyond the per-cluster configured posture |
</threat_model>
