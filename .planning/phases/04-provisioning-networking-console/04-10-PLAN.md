<objective>
Build the `/create` wizard route shell: the wizard chrome (header, stepper rail, footer), Step 1 (the six-path PathPicker), the step-orchestration surface, and the sessionStorage-backed draft store. This plan owns `routes/create/+page.svelte` and the wizard chrome so the three sibling wizard-step plans (04-11 LXC, 04-12 VM, 04-13 Cloud-Init) plug their per-path step components into a stable shell without conflict.

Building it once here — after the API layer + primitives ship in 04-09 — prevents the wizard `+page.svelte` becoming a four-plan merge conflict and keeps each frontend plan under the file-count threshold.

Output: `routes/create/+page.svelte` (+ `+page.server.ts`), `WizardChrome.svelte`, `PathPicker.svelte`, and the `wizardDraft` store.

**`frontend/src/lib/stores/wizardDraft.svelte.ts`** — a Svelte-5 rune store (modelled on `stores/jobs.svelte.ts`): holds the wizard draft — `path` (the chosen provisioning path), `step`, and a per-step `formData` bag. Exposes `clear()` (called on wizard complete or discard). No server-side persistence (UI-SPEC §Form-state persistence — v1 is `sessionStorage` only). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /create SSR loader | The wizard route is auth-gated; an unauthenticated user is redirected to login |
| browser sessionStorage ↔ wizard draft | Wizard draft is client-only state — no secrets are persisted to sessionStorage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10-01 | Spoofing | Unauthenticated wizard access | mitigate | `create/+page.server.ts` is an auth-gated SSR loader (the `admin/teams/[id]` analog) — an unauthenticated user is redirected to login before the wizard renders; the real authorization is enforced server-side on the create POST (Plan 04-04) |
| T-04-10-02 | Information disclosure | Secrets persisted to sessionStorage | mitigate | The `wizardDraft` store persists only non-secret wizard form state (path, sizing, selected names) — no passwords, no tokens; `cipassword` (Cloud-Init) is explicitly excluded from the persisted bag |
| T-04-10-03 | Tampering | Stale/forged wizard draft replayed | accept | A tampered `sessionStorage` draft only pre-fills wizard fields the user can see and edit; every value is re-validated client-side and re-authorized server-side on submit — a forged draft cannot bypass quota admission or tenancy checks |
</threat_model>
