- `HelpTooltip` → `tooltip` (or `popover` for the longer text + "Learn more" link variant) + `HelpCircle` icon

**Cloud-Init YAML pane (D-09): hand-rolled read-only render.** No code-editor library is imported. The pane is a styled, scrollable `<pre>` block; PVE-injected lines (D-10) get a dimmed (`text-muted-foreground`) treatment plus a "PVE default" `Badge variant="outline"` rendered inline at line-end. Rationale: the pane is transparency, not raw editing — a syntax-highlighting editor library (Monaco ≈ 2 MB) is unjustified bundle weight for a read-only preview. This mirrors the Phase 3 hand-rolled snapshot tree and the Phase 2 hand-rolled `Sparkline` decision. The checker validates the absence of any code-editor npm dependency (`monaco-editor`, `codemirror`, `@codemirror/*`, `prismjs`, `shiki`).

**noVNC console (CON-01..03): plain iframe, no embedded library.** The Console tab renders an `<iframe>` whose `src` is the GUI's own reverse-proxied noVNC URL (the GUI proxies the WebSocket — no direct Proxmox exposure to the browser). The `vncticket` is minted server-side **on user click** (Pitfall 3, ~30–40s lifetime), never on page load. The iframe is **not** rendered until the user clicks "Open console" — see §Console tab contract.

## Layout Contracts

### Create wizard (`/create`) — D-01, D-03

A single unified wizard on one route. Step 1 is a six-card path picker; the wizard then branches into path-specific steps. One wizard chrome throughout. Stepped, with Back/Next and a progress indicator — consistent with the Phase-1 four-step first-run setup wizard.

**Wizard chrome contract:**
- Header: title "Create" (Heading 18/600) + a close `X` (top-right). The icon-only `X` close button **must** carry `aria-label="Close wizard"`. Closing mid-wizard prompts an `alert-dialog`: "Discard this draft? — Your wizard progress will be lost." / CTA "Discard draft".
- Stepper rail: a horizontal stepper (default) above the step body, OR a 200px left vertical rail — executor picks one, stays consistent. Active step `bg-primary`; completed steps `--success` with a check; future steps `--muted`. Step labels are Label 13/500.
- Footer bar: 64px sticky, `[← Back]` left (`variant="ghost"`, hidden on Step 1), `[Next →]` right (accent). On the final Review step the right button becomes the path-specific provisioning CTA (see Copywriting Contract).
- The step body is `max-w-[45rem]` centered, **except** the Cloud-Init step which uses the full content width for its two-pane layout.

**Step model (D-03):** `Path → Source/Template → Resources → Network → Cloud-Init → Review`. Steps are path-conditional:

| Path | Steps shown |
|------|-------------|
| Plain LXC (vztmpl) | Path → Template → Resources → Network → Review *(no Cloud-Init step)* |
| Community Script | Path → Script → Resources → Network → Review *(no Cloud-Init step; D-07 script-option fields render inside the Script step)* |
| Cloud-Init image | Path → Image → Resources → Network → Cloud-Init → Review |
| PVE template clone | Path → Template → Resources → Network → Cloud-Init → Review |
| Blank + ISO | Path → ISO → Resources → Network → Cloud-Init → Review |
| Clone existing VM | Path → Source VM → Resources → Network → Cloud-Init → Review |

The Cloud-Init step appears on **all four VM paths** (D-13) and is **absent** from both LXC paths.

**Path-picker (Step 1) contract:**
- Six selectable cards in a responsive grid (3-up ≥1024px, 2-up ≥640px, 1-up below), 160px tall, min 240px wide, `sm` grid gap
- Each card: an icon (24px), a title (Body 14/600), a one-line description (Label 13/400 muted)

- `Next` is disabled until a path is chosen

**Resources step contract:**
- Fields: target node (`Select` — see Node-fit selector below), storage (`Select`, content-type filtered — Pitfall 16), CPU cores (number), Memory GB (number), Disk GB (number)
- For LXC paths the step additionally shows the LXC-07 toggles: "Unprivileged container" (`Switch`, default **on**), "Nesting" (`Switch`, default off), "Features" (a small checkbox group — keyctl, fuse, etc.)

**Node-fit selector (D-24, VM-10):**
- The target-node `Select` reads **live free** node resources when the picker renders (fresh read, not cached)
- A node that cannot fit the requested CPU/RAM is **disabled** (un-pickable) in the `Select`
- Each disabled option shows the reason inline (Label 13/500 muted): "node-1 — 2 GB free, needs 4 GB"
- If **every** node is blocked, a `bg-warning/10` notice appears above the selector: "No node currently has room for this size. Reduce CPU or memory, or try again later." and `Next` is disabled
- Node-fit re-evaluates when the user changes CPU/Memory on the Resources step

**Review step contract (Claude's discretion — pinned):**
- A read-only summary grouped into `card` sections mirroring the steps: Path, Source, Resources, Network, Cloud-Init (when present)
- Each section has an "Edit" link (`variant="link"`) jumping back to that step
- The final provisioning CTA lives in the footer (path-specific label — see Copywriting Contract)
- The live quota-delta line repeats here for a last confirmation

**Post-submit landing (D-04):**
- Provisioning is async (202 + arq job; the VMID is reserved pre-create via the Phase-3 `reserve_vmid`)
- On submit the wizard **closes** and routes to `/inventory/{cluster}/{vmid}` (the new resource's detail page)
- The detail page shows a **provisioning banner** (see below) while the create job runs; the Tasks drawer also carries the job
- A `sonner` toast confirms: "Creating {name}… — Track progress in Tasks." (default/info)

**Form-state persistence (Claude's discretion — pinned):** wizard state is held in a `sessionStorage`-backed store keyed by a draft id, so an accidental refresh mid-wizard restores the user's progress and selected path. Closing the wizard (or completing it) clears the draft. No server-side draft persistence in v1.

**Empty network scoping (D-19):** if the team has no SDN networks scoped and the cluster is SDN-capable, the Network step shows only legacy bridges (default-visible) — never an empty picker. If a cluster has **neither** a usable bridge nor a scoped SDN network, the step shows the `bg-warning/10` "no networks" notice and `Next` is disabled.

**Single-word `/inventory` "Create" CTA — accepted convention.** The page-header button on `/inventory` is intentionally the single word "Create" with no noun. It is an **inventory-screen page-action affordance** — its noun is supplied by the page it lives on (the VM/LXC inventory) and by the wizard it opens, whose Step-1 heading is "Choose what to create". Spelling out a noun here is ambiguous (the button creates either a VM **or** an LXC — the path is chosen inside the wizard), so a single-word page action is the correct, deliberate choice. This mirrors the Hetzner-Cloud "create server" entry-point convention and the Phase-2 list-screen action pattern. Every **terminal** provisioning CTA inside the wizard footer is a full verb+noun ("Create container", "Create VM", "Deploy script", "Clone VM") — the verb+noun rule applies to the committing action, and the `/inventory` button merely opens the wizard.

## Accessibility Floor (Phase 4)

Inherits the Phase 1 + 2 + 3 accessibility floor. Phase 4-specific minimums:

- The `/create` wizard is a keyboard-complete flow: the stepper communicates progress via `aria-current="step"` on the active step; Back/Next are real buttons; each step's heading is the focus target on step change.
- The six path-picker cards are a single `radio-group` (`role="radiogroup"`), each card a `role="radio"` — arrow keys move selection, Space/Enter confirms; the selected card carries `aria-checked`.
- Path/node/network selection is **never color-only**: the selected path card carries a visible check icon **and** the `aria-checked` state; disabled (node-fit-blocked) options carry `aria-disabled` plus the visible reason text.
- The Cloud-Init YAML pane is `aria-hidden` decoration (it is a derived render) — the form fields carry the meaning; hard validation errors are wired to their fields via `aria-describedby` and announced.
- The Cloud-Init "PVE default" distinction is **not** color-only — the dimmed lines also carry the literal "PVE default" badge text.
- The noVNC `<iframe>` carries a `title` attribute ("Console for {name}"); the "Open console" / "Reconnect" buttons are real, labelled buttons; the iframe is not auto-focused on render (a noVNC iframe grabbing focus on mount would trap keyboard users).
- The notification bell button has an `aria-label` with the live unread count; the panel is a `role="menu"`/dialog with focus trap + ESC-close; row state (`succeeded`/`failed`) is real text + an icon, never color-only; opening the panel does not steal focus into an item.
- Every `HelpTooltip` `?` icon is a focusable `button` with an `aria-label`; the help text is reachable on keyboard focus, not hover-only; the "Learn more" link is a real `<a>`.
- The provisioning banner has `aria-live="polite"` so the running→succeeded/failed transition is announced once.
- All wizard form fields keep visible labels (not placeholder-only); required fields are marked; the `cipassword` field reuses the Phase-1 `PasswordInput` (show/hide toggle, labelled).
- Contrast: all Phase 4 surfaces reuse Phase 1 tokens already validated AA in both light and dark modes — no new colors, so no new contrast risk.

## Implementation Notes for Executor

1. **The three ROADMAP-mandated research spikes gate implementation** — SDN reload/applied semantics + PVE version floor; noVNC `vncticket` single-encoding + reverse-proxy WebSocket headers + self-signed-cert handling; community-scripts non-interactive (whiptail-bypass) execution + `pct exec` output streaming + metadata-format stability. The planner sequences these first. This UI-SPEC describes the **target UI**; if a spike result forces a UI change, this spec is updated — not the code silently.
2. **The wizard is one route, one chrome (`/create`).** Step 1 is the six-path picker; steps branch per path per the Step Model table. Do not split into separate VM/LXC wizards (D-01).
3. **Provisioning is async — 202 + arq job.** The wizard closes on submit and routes to the new resource's detail page with the provisioning banner (D-04). The VMID is reserved pre-create via the Phase-3 `reserve_vmid` (per-cluster `asyncio.Lock` + 60s reserved set — Pitfall 1). No UI surface blocks on a UPID poll.
4. **Provisioning is non-idempotent** (Phase-3 D-16) — a failed create shows **no Retry button**; the user re-runs the wizard. The Retry affordance from the Phase-3 contract does not apply to create jobs.
5. **The Cloud-Init YAML pane is read-only (D-09)** — the form is the sole input; the pane is a hand-rolled `<pre>` render, no code-editor library. PVE-injected lines are dimmed + carry a "PVE default" badge (D-10, VM-06).
6. **Cloud-Init validation is block-hard / warn-soft (D-12)** — hard errors disable the CTA; soft warnings are non-blocking. Mirrors the Phase-2 D-08 admission pattern.
7. **The noVNC iframe is never rendered on page load** — the `vncticket` is minted **on the "Open console" click** (CON-02, Pitfall 3 — ~30–40s ticket lifetime). The ticket URL must be URL-encoded **exactly once** (the noVNC spike confirms this — double-encoding silently fails). All console traffic is reverse-proxied through the GUI (CON-03).
8. **The notification bell reads the existing `jobs` table** + a per-user last-seen timestamp (D-23) — **no new notification table**. Scope is task completions only (D-22).
9. **Node-fit blocks unfit nodes (D-24)** — unfittable nodes are disabled in the selector with a visible reason; node-fit reads **live free** node resources fresh when the picker renders.
10. **Legacy bridges are default-visible; SDN needs admin granting (D-19)** — the network picker auto-detects SDN-capable clusters (D-21); the Networks admin tab (D-18) scopes per team, per cluster.
11. **ISO downloads are not admin-gated (D-17)** — any authenticated user can trigger an ISO/cloud-image URL-download; it runs as a job.
12. **Community-scripts run inside the fresh LXC via `pct exec`** (Pitfall 10) — never on the host. LXC-04 source + commit hash + last-reviewed date are shown **before** deploy, derived from the active catalog pin; the attribution notice is mandatory.
13. **Two new official shadcn-svelte blocks** (`radio-group`, `stepper`) — pull from the official registry. If `stepper` is unavailable, hand-roll it from the Phase-1 setup-wizard pattern. No third-party registry, no tree/wizard/editor npm dependency.
14. **All copy in this contract is the user-facing copy** — executor uses it verbatim. Changes require updating this spec, not silently in code.
15. **No new design tokens, sizes, weights, or icons beyond the cumulative allow-list.** Phase 4 composes entirely from the established slate design system at exactly 2 declared weights (400 + 600; 500 is the inherited optical-axis label exception). The single declared spacing exception is the full-width Cloud-Init wizard step.
